# bn reference — reading

Read-command catalog for the `bn` skill. Open when surveying/decompiling. See `../SKILL.md` for the map.
## Commands

```bash
bn target info
bn target list [--format json]                       # open targets + their selectors; `selector` is what -t takes
bn function list [--count] [--min-address 0x401000 --max-address 0x40ffff]
bn function list [--sort {address|size|name}] [--reverse] [--min-size 64] [--demangle]
bn function list [--named | --unnamed]               # meaningful names vs BN's auto sub_* (import thunks in neither)
bn function search attachment [--count]              # --count here = MATCHES, not the whole-binary total
bn function search --regex 'attach|detach|follow'
bn function search <q> [--sort … --reverse --min-size N --demangle]
bn function info <fn> [--verbose] [--blocks]         # --blocks: basic-block address ranges + edges
bn decompile <fn> [<fn> …] [--addresses] [--lines 40:80] [--force-analysis] [--include-annotations]
bn il <fn> [--view {hlil|mlil|llil}] [--ssa]          # --level is an accepted alias for --view
bn disasm <fn> [--lines 40:80 | --count 20]
bn disasm <addr> --linear [N]                        # up to N (default 32) units: one physical instruction or one undecodable .byte byte
bn xrefs <fn-or-addr> [--limit 20]
bn xrefs --field <Struct.field>
bn callsites <callee> --within <fn>
bn callsites <callee> --within-file <path>
bn evidence function <fn> [--context 2]              # per-call ABI args (LLIL/MLIL/HLIL + raw disasm) + thunk detection
bn evidence xrefs <fn-or-addr> [--limit N]           # inbound refs annotated with section/segment/symbol/disasm
bn evidence table <addr> [--entries N] [--stride N]  # interpret memory as a pointer/vtable table (Thumb-normalized)
bn evidence table <addr> --record-size N --ptr-fields o1,o2  # mixed-record mode: scalar + pointer fields per record
bn evidence table <addr> --record-size N --field cmd:u32@0 --field name:char[16]@8   # typed scalar/string fields
bn evidence calls <reg-fn> --arg-struct N --field type:u8@2 --field cb:ptr@16  # stack-descriptor fields per callsite
bn evidence message <type-string> [--limit N]        # protobuf/RTTI type-name -> xrefs -> nearby metadata table windows
bn evidence init [--limit N]                         # .init_array/.ctors constructor-pointer summary
bn evidence orient                                   # one-shot triage digest under a single read lock: target + analysis state, imports, strings sample, sections
bn evidence surface                                  # hidden code surface: init/ctor + vtable/dispatch tables + data-referenced code BN missed
bn evidence virtual-call --at <addr> [--providers <selector>]   # resolve an imported abstract/interface virtual call to the provider's vtable method
bn trace <fn> <addr> [--arg N] [--interprocedural]   # backward SSA slice: trace where a call argument originates
bn dataflow defuse <fn> --var <name|local_id|name#version>   # SSA def site + use sites of one variable
                                                    # a use that is argument set-up for a call whose
                                                    # recovered model dropped its stack-passed args is
                                                    # reported as a `hint: call ... call-model truncation`
bn dataflow callgraph <fn> [--direction {callees|callers|both}]   # resolved edges; indirect targets via value-set
bn dataflow values <fn> --at 0x401234                # value-set (possible values) at an instruction
bn taint models [--role {source|sink|propagator}] [--class overflow_len] [--present] [--callsites]   # known sources/sinks; --present needs a target
bn taint forward -f <fn> --source param:0 [--sink-class recv_overflow]   # untrusted data source→sink across calls (methodology → the `bn-vr` skill)
bn taint backward -f <fn> --sink arg:memcpy:2         # slice a sink's args back to their origin (`bounded: true` = provably bounded)
bn function cfg <fn> [--view {asm|mlil|hlil}]        # basic-block graph: blocks, their instructions, and the typed edges between them
bn function structured-il <fn>                       # flat per-instruction list: op plus vars_read/vars_written, no block partitioning
bn proto get <fn>
bn local list <fn>
bn local list --frame <fn>                           # stack frame map: one row per distinct stack offset, saved-register/canary markers, bytes to the canary
bn data vars --start <addr> --end <addr>             # typed data variables in an address window (the window is mandatory)
bn data symbols [--limit N] [--offset N]             # named DataSymbols, internal ones included (paged: 100 by default)
bn read 0x... --length N [--encoding {hex|bytes}]   # address is positional; --address 0x... is an accepted alias
bn types [--query <q>]
bn types show <name>
bn struct show <name>
bn class list [--all] [--no-stl] [--query <substr>]   # C++ classes from demangled symbols + RTTI (+ your own declared class types under --all)
bn class show <Name>                                  # one class: methods, vtable, size, bases, instances; falls back to a class type you declared
bn strings [--query <q>] [--regex] [--min-length 5] [--section .rodata] [--no-crt]
bn imports
bn exports [--count]                                 # global/weak definitions from any symbol table, not loader-visible exports
bn go functions [--summary | --count]                # recover Go names from .gopclntab (then `bn go rename`, a mutation)
bn sections [--query <q>]
bn tag list [--type Bookmarks --query <substr>]      # tags at all scopes; `--type Bookmarks` is the bookmarks tag
                                                     # UNFILTERED it walks EVERY function (function tags + address tags);
                                                     # narrow with --function <fn>, or --data for data tags alone
bn tag get 0x401000                                # tags at one address
bn tag get --function <fn>                          # whole-function tags
bn tag types                                         # tag types (built-in + custom)
bn comment list [--query <q>] [--scope {all|address|function}]   # `all` (default) includes function docs
bn comment get --address 0x...                     # address comment
bn comment get --function <fn>                     # function documentation comment
bn bundle function <fn> [--out bundle.json]          # export; does not mutate the BNDB
```

Notes:

- `function search` is a case-insensitive substring search. Use `--exact` for a known API, `--word` for an identifier token, or an anchored `--regex` for a family. A regex-shaped zero-hit literal query may be retried as a regex; `regex_fallback` discloses that choice. Confirm a source or sink against the import and actual call target, not its name alone.
- `function list --count` counts all functions; `function search <query> --count` counts matches. `--sort size --reverse --min-size N` is useful for large functions. `--named` / `--unnamed` separate meaningful names from auto `sub_*` names.
- `exports` lists global/weak function and data definitions from any symbol table in BN's combined symbols; `exports list` is an alias, and `--count` counts that same population. It does **not** establish dynamic-loader visibility. On ELF, a global definition may exist only in `.symtab`, not `.dynsym`; use `readelf --dyn-syms` or `nm -D --defined-only` to inspect the dynamic table instead. The synthetic ELF case reported in [#921](https://github.com/m4ul3r/bn/issues/921) had 235 definitions under `bn exports --count` but only 2 under `nm -D --defined-only`: those are different populations, not evidence that all 235 are dynamically exported.
- **Duplicate function start addresses are disclosed (#757).** Binary Ninja can hold more than one Function record for one start address. Where an answer holds such an address it publishes `duplicate_starts_collapsed` / `duplicate_starts_unresolved`, and every text face that answer reaches discloses it too. This entry states no more than that on purpose: every summary of what the collapse does to a given answer has been false on some shape of it, so the answer carries that truth and this page does not restate it.
- `evidence orient` reports `existing_annotations` at the top level. A restored `.bndb` can carry earlier names and comments. `decompile` omits stored annotation bodies by default; `--include-annotations` opts in. Redaction covers matching standalone or inline `//` annotation lines, not arbitrary block comments or differently rendered text. Use `--addresses` when mapping a rendered line back to code.
- `strings` ranks a dump by the section a string sits in: `.rodata`-like (ReadOnlyData) first, `.data`-like next, then code bytes that decode as text and linker metadata, in address order within each tier; where sections overlap the narrowest claiming one decides. An address no section claims is noise only when the view has a ReadOnlyCode section and the address is in an executable segment; on a raw image or a section-header-stripped ELF (BN adds only `.synthetic_builtins`) nothing is ranked and the dump is plain address order. `noise_strings` / `noise_sections` name the last tier and `data_sections` the data sections the listing drew on; the text tip names them only when noise is non-empty, recommends `--section <top data section>` only on an unfiltered dump, and `--section` pins one section in address order. `evidence orient` samples only the first two tiers (`sample_sections` says which, in sampled order) and names the fallback in `sample_fallback` when a view has no strings there.
- `bn decompile handle parse_file main` uses one bridge call and preserves the requested order. A missing identifier keeps its row and makes the command exit 2. One identifier retains the single-function `.text` shape; several return `{"kind": "decompile_batch", "requested": 3, "resolved": 2, "functions": [...]}`. Read `.functions[].decompiled.text`, not `.items[]`. An `analysis_skipped` stub is not a body; `--force-analysis` analyzes that function and can be slow.
- `decompile` can disclose a **struct layout candidate** in `.warnings` (also printed in text mode) for an incoming `void *` parameter. The witness is direct MLIL-SSA loads/stores at two or more distinct constant byte offsets, all matching complete flat scalar members' offsets and widths in exactly one compared struct layout. Every other use of the incoming pointer value except a comparison (a copy into another variable, a PHI, a derived pointer, a call argument, a stored value, or a taken address) disqualifies the parameter, because accesses through that value would escape the witness. The note names the parameter, layout, fields, and access widths, and states that layouts holding the offsets in nested, union, array, or base-class members were not compared; it is evidence of layout compatibility, **not recovered type identity**. Review with `struct show` and `disasm`, then use `proto get` and explicitly apply the full edited prototype with `proto set`, preserving the other parameters, qualifiers, and calling convention. For example, if the current prototype is `uint64_t handle(void *c)` and the candidate is confirmed, use `bn proto set handle 'uint64_t handle(struct cfg *c)'`.
  - This assistance never applies a type or changes the rendered body on read; already-typed pointers keep their existing rendering. Batch decompilation carries the same per-function warnings.
  - Known layouts include loader-provided and other auto-defined structs already in the view, not only user declarations. A missing analyst-defined type does not mean no compatible layout exists; adding it can make an existing match ambiguous.
  - Named scalar member types are resolved through up to 16 typedef references before matching, only for members at an observed offset and width, with exactly one view type lookup per hop (by ID, or by qualified name when no ID is present). The shared resolver used by `struct show` and class declaration reads enforces the same lookup budget and detects cycles by reference identity, not Python wrapper identity. An unresolved ID is not retried by name. Unresolved, cyclic, or longer chains and non-scalar terminal types do not supply a member witness. Distinct concrete structs remain distinct candidates even when their members differ only in typedef spelling; aliases of a whole struct do not add candidates.
  - Matching distinguishes a positive scalar witness, an excluded layout, and an unclassifiable member. An unresolved, cyclic, or over-budget member at a matching offset and width, or an access overlapping a bitfield's storage unit, overlapping members, or the span from a zero-width member (an unresolved named type or flexible array) to the end of its layout, cannot supply a hint, but an otherwise compatible flat layout containing it blocks any claim of a unique candidate. A trailing flexible array covers no bytes. A base-less `class` layout, and a layout whose members overrun its recorded width (for example after redeclaring an embedded type), are compared like a struct and block uniqueness when compatible, but are never themselves suggested. A layout whose flat scalar members do not match an observed offset/width, or whose observed member is non-scalar, is excluded from the comparison; that is a scope limit, not proof that it cannot be the parameter's type. Opaque types elsewhere in the view, including unobserved members and bitfields away from every access, do not by themselves suppress hints.
  - Scope is deliberately narrow: no pointer-alias/dataflow recovery, computed indexes, reassigned pointer values, class suggestions, or comparison of accesses that land inside a nested struct, union, array, or base-class member. Such layouts can be compatible yet neither block nor appear, which the warning discloses. Conflicting widths/offsets or multiple matching layouts produce no suggestion. A missing hint is **not** proof that no struct could fit, and a hint is **not** proof that no other type fits.
- `disasm --lines START:END` and `--count N` count rendered function rows, not bytes. `disasm <addr> --linear N` walks physical instructions and undecodable `.byte` units outside recovered blocks. For width, branch, or bounds claims, inspect the instruction operands. On Thumb, include the preceding `IT` instruction and every covered instruction.
- `class list` groups demangled C++ methods and RTTI. Its default favors RTTI/constructor-supported classes; `--all` also shows name-only and user-declared class/struct/union types. A name-only cluster may be a namespace; a declared-only card does not prove methods or vtables are absent. One class demangled under two spellings (`Holder<std::string>` and its `basic_string` expansion) is one card, reachable by either through `class show` and `--query` alike; the other spellings are `aliases`. `class show` reports ambiguity and scan caps rather than choosing a same-leaf class or treating a truncated vtable as complete. A vtable ends at the next object (an RTTI record or vtable BN names at that address, or a typeinfo's vptr), never inside it; BN's own `VTable` width is reported as `bn_vtable_slots` but never bounds the walk, because BN stops that struct at the first null word and an abstract class's zeroed destructor entries sit mid-table. An imported class's typeinfo is an import slot: `bases` is empty with a note, not decoded from GOT words. A `secondary vtable` recovered by typeinfo backwalk is `[rtti]` when its slots are this class's `_ZThn<N>_` thunks at that offset-to-top or BN's own `vtable for X{for `Y'}` symbol names it, else `[heuristic]`; a candidate whose word[0] is a mapped pointer or out of bound is listed under `rejected_secondary_candidates` with the observed reason. Confirm a `[heuristic]` secondary with `evidence table` before reporting an inheritance edge.
- A decoded vtable's `address` is the Itanium object head; slot zero is at `address + 2 * pointer_size`. In stripped binaries BN may synthesize `vtable for X` on slot zero instead. The class lens normalizes that address only after reading a preceding zero offset-to-top, local typeinfo for the same class, and fully resolved nonvirtual RTTI ancestry; it does not move BN's symbol. ABI selector provenance first checks the object head two words before the typeinfo vptr, so an adjacent unrelated extern at the exact vptr cannot override it. Virtual-base ancestry (including inherited virtual bases), imported/unresolved bases, unreadable base records, or an unknown ABI RTTI selector leave the original address and conservative `no_local_vtable_body`: construction tables share the same header, even when there is only one candidate. An existing object head is kept, import/GOT aliases are not normalized, and a nonzero-offset candidate remains the secondary backwalk's responsibility, never promoted to a primary. Stored-global instance lookup uses this proven slot-zero address point for decoded layouts, including capped or unreadable slot scans. An undecoded entry or `no_local_vtable_body` does not authorize adding two pointers: lookup keeps the original symbol address. Named VTT and construction-table objects are excluded only within BN's proven data-object width; without a width, only their first word has proven ownership. Consecutive address-point pointers and the next symbol do not prove an untyped VTT's extent: an unnamed neighboring object can have the same vptr. Remaining references are preserved with a note that they may include untyped ABI entries; stored-global totals count references, not proven instances. Unnamed ABI containers are not identified.
- `evidence surface` surveys constructors, pointer tables, and executable data-referenced addresses BN may not have made functions. It is read-only; candidate `code_likely` and `decode_depth` are triage signals, not proof. Verify a candidate with disassembly before `function create`. `evidence init` handles pointer width, endianness, and ARM/Thumb normalization. `evidence table` distinguishes pointer arrays from mixed records; declare record stride and pointer or scalar fields only when the layout is known.
- `evidence calls <reg-fn> --arg-struct N --field name:type@offset` reads a stack-built descriptor at each registration call. `ptr` resolves a callback/data symbol when possible; unknown, computed, and merged values remain marked. Confirm heuristic values at `source_address`. `evidence function` pairs calls with raw ABI and IL evidence; its `argument_confidence` and arity warnings matter when the decompiler guesses arguments. `evidence virtual-call` may return several providers or a typed unresolved reason; a capped scan is not absence.
- `trace <caller> <call-addr> --arg N` follows MLIL SSA backward within the caller. `--interprocedural` follows return values into internal callees; it does not map callee parameters up into callers or follow output-pointer writes. The boundary leaf is `out_param_not_followed` locally or `interprocedural_out_param_not_followed` with `--interprocedural`. Use xrefs and another trace to climb callers.
- `function cfg` contains block edges. In asm view, edge `to` values are addresses; in MLIL/HLIL they are IL instruction indexes. `data vars` requires an address window; `data symbols` lists internal DataSymbols that exports omits. These read under the shared read lock, unlike arbitrary `py exec`.
- `bn read <addr> --length N` reads mapped bytes, with a hard ceiling of 100000 bytes per request. A short mapped read sets `short_read`; a request above the ceiling sets `capped`. Either is partial, with `requested_length` and a note. Under `--encoding bytes`, the note is visible on stderr while stdout carries the raw bytes. An unmapped start errors.

Before an unfamiliar large read, use `--estimate-output` to measure its output without emitting the body; then slice with `--limit`, `--lines`, or `--out`.

## Data-symbol pagination cost

`data symbols` defaults to 100 rows, but **every page rebuilds the full named-symbol population**: the bridge enumerates all DataSymbols and filters out unnamed ones again to compute the honest `total`. Only row construction and serialization are limited to the requested window. There is no population cache shared between pages; walking every page repeats the full scan under the shared read lock on every request and multiplies aggregate lock-hold cost.

For an index that needs every symbol, prefer one whole-set request:

```bash
bn data symbols --offset 0 --out /tmp/bn-data-symbols.json   # omit --limit: uncapped, one request
bn data symbols --offset 0 --limit 50000 --format json     # one large page; whole set only if total <= 50000
```

`--out` removes the default page limit, but an explicit `--limit` still wins and a nonzero `--offset` still skips rows. Read the artifact named by the output envelope. Programmatic callers can send op `data_symbols` with `{"offset": 0, "limit": "all"}` for the whole set; the response echoes `limit: null`. Omitting `limit` or sending `null` instead requests the default 100-row page, not the whole set; CLI `--limit` accepts a positive integer, not `all`. A single request still pays one full population scan and builds all requested rows while holding the read lock. Check `has_more` before treating a numeric-limit result as complete.

## JSON reads and coverage

Most collections use `{kind, items, total, offset, limit, returned, has_more}`. Inspect `kind` before selecting a container. Common leaves:

| Read | Rows or payload |
|---|---|
| `strings` | `.items[].value` |
| `function list` / `function search`, `imports`, `exports` | `.items[].name`, `.items[].address` |
| `sections` | `.items[].name`, `.start`, `.end`, `.length`, `.semantics` |
| `types` | `.items[].decl`, `.layout`, and aggregate `.members[]` |
| `local list` → `.items[]` | same list retained under `.locals`; rows carry `.local_id`; stack rows carry `.distance_to_next_slot` (slot pitch, not object size; the top negative slot measures to entry-SP offset 0 even when no slot is recovered there) |
| `local list --frame` → `.items[]` | one row per distinct stack offset: `.storage`, `.kind` (`local`/`saved_register`/`canary`/`return_address`/`caller_frame`), `.names`, `.distance_to_next_slot`, `.to_canary`, `.variables[].local_id`; top level `.canary_storage`. Canary evidence requires a full-ABI-word guard load and copy; TLS identity comes from architectural registers, not mutable local names. |
| `xrefs` | `.items[]`, with `.kind` and `.caller_function` per reference |
| `callsites` | `.items[].caller_static`, `.callee`, `.containing_function` |
| `comment list` | `.items[].comment` and `.scope` (`address` or `function_doc`) |
| `tag list` | `.items[]`; `tag get` instead uses `.tags[]`; `tag types` uses `.tag_types[]` |
| `evidence function` | `.calls[]`, plus pagination metadata |

Addresses in JSON are hex STRING values such as `"0x401000"`; convert before arithmetic. `row_fields`, when present, lists available row keys. A zero-hit read may have no schema for a kind without a declared schema.

**Absence requires a complete read.** Check `has_more`, caps, and scan notes. In particular, an import xref scan may return `items: []` with `truncated: true` and `scan_note`; text prints `note: the caller scan was TRUNCATED`. That means unknown, not zero callers. For high-fan-in `callsites`, `total: null` is a lower bound: inspect `total_lower_bound`, `scan_truncated`, `caller_scan_truncated`, and `caller_scan_note`. Either truncation flag prevents a complete-caller claim. A determined integer total must remain stable across pages.

`Client.collect` and both `bn-kernel` backends report callsite coverage from the final request's cumulative scan, not the first page or a sum of page counts. The scan starts at row zero and includes lookahead, so `callers_scanned` and `total_lower_bound` need not equal the number of returned rows, especially with finite limits, nonzero offsets, or zero-row probes. An exact `total` replaces the lower bound; `total_lower_bound` is then omitted. A terminal `has_more: false` can still accompany `caller_scan_truncated: true` and `total: null`: all discovered rows were exhausted, but caller enumeration remains incomplete.

For taint JSON, forward flows are `reached_sinks[]`, each with `.sink` and `.path`; backward results are `slices[]`, while top-level `sinks` repeats the query. `sink_status[]` discloses whether a backward sink was seeded or proven `bounded`. On a zero-sink forward run, read `diagnostics.safe_to_report_all_clear`: weak seeds or unmodeled-call assumptions can withhold an all-clear even with no leaves or truncation. A true gate only supports absence of modeled sink flow under that analysis, not absence of bugs. A backward run reports `diagnostics.safe_to_report_complete_slice`; it is false whenever a frontier leaf remains, the run was truncated, or any slice `origin.kind` is `unresolved` (counted under `diagnostics.frontier.unresolved`).

A slice that reaches a local buffer's address continues through its writers at the consumer's memory version. This includes folded/member addresses, SSA aliases, stores, modeled fills, length operands, and recursive source-buffer walks at each writer's own input memory. Earlier parameter/source inputs are retained beside later literal appends. Coverage is keyed by the **consumed region**, not the enclosing aggregate: `snprintf(r.cmd, 64, "%s", input); popen(r.cmd, "r")` need not initialize `r.id`. Writes proven disjoint from the consumed region do not contribute source operands, origins, or source-buffer prerequisites; a known zero-byte write has no destination provenance. This exclusion uses the final consumer's bounds (including proven string termination), not an intermediate NUL that a later write may overwrite. Unknown, overlapping, and may-alias writes remain in the walk. Byte consumers such as `write(fd, r.cmd, 64)` require a definite write extent containing all 64 bytes; a C-string producer initializes only the string at its start, not the unused tail or a later suffix. A byte fill alone does not prove string termination. Verified copied NULs (including lifted constant-data bytes), zero fills, or an explicit terminator after a definitely initialized prefix can establish it. A terminated suffix such as `strcpy(buf + 5, input)` also requires proof of the preceding five bytes at that writer's input epoch. Stack-slot pitch and canary distance are not used as object capacities.

A modeled destination is a **may-write**, not an initialization guarantee. Zero-length fills cover nothing. Short or unknown extents, variable indexes, may-alias pointers and appends cannot certify an uncovered prefix/suffix. Requested I/O lengths (`read`, `recv`, `fgets`, etc.) do not prove actual initialization: short/error returns remain uncertain even when the requested count equals the buffer size. A later write can destroy previously established string termination, but a zero-byte or provably disjoint write does not. Zero fills retain their full known-NUL intervals, not a chosen sentinel: zeroing 64 bytes before either `read(fd, buf, 63)` or `read(fd, buf + 63, 1)` leaves a usable NUL with an initialized prefix. Middle and successive bounded writes subtract from those intervals; proof is lost when no usable terminator remains. An uninitialized buffer gains no initialization proof from the same reads. Appends preserve termination, not its old position. The every-path memory-phi rule and memory-chain budget remain in force. An `address_of_local_unresolved` leaf discloses missing coverage with `region: {offset, width, kind}` (`null` means unknown; `kind` is `bytes`, `cstring`, `bounded_cstring`, or `unknown`), or names an opaque writer, escaped/unresolvable pointer, global input, or truncated chain (`stats.truncation_cause: ["memory_chain"]`). Read-only constant storage is literal input; writable globals remain frontiers. A `{}` callee is disclosed in `assumptions`: it promises no tainted flow, not full initialization or preserved termination.

The local-buffer **memory-chain budget measures proof work and storage, not just chain depth**. One shared allowance of 256 work units covers memory visits, PHI inputs, proof transformations/retained alternatives and NUL-interval processing, including recursive prefix proofs and loop-invariant retries. Work is charged before expansion; deduplication does not refund it. A shallow chain with many independent branches can therefore exhaust the allowance even when every path would preserve a NUL. Exhaustion stops the proof rather than dropping alternatives or treating an empty proof set as coverage: `stats.truncated` is true with cause `memory_chain`, an `address_of_local_unresolved` leaf explains the cut, and `safe_to_report_complete_slice` is false. This is a per-region proof allowance, not a process-memory or whole-analysis runtime limit.

Loop coverage is a bounded memory-SSA proof, not arbitrary induction or a guarantee about compiler shapes. A neutral backedge is used only inside its active traversal; results depending on that assumption are not reused at another PHI arm. This preserves an unwritten entry path at a later loop-exit join regardless of arm order (#950). Already initialized entry regions and independently covering loop writers can still prove coverage. Revisited cyclic paths spend the same allowance, so complex loops may truncate even when their coverage could be proved by a stronger analysis. A backedge cannot supply an exact NUL location; unknown/indexed fills and unions of partial stores do not establish whole-region initialization.

Loop-carried escape state is also a may-property: an address stashed at the bottom of one iteration can let an earlier unmodeled call write the buffer on the next iteration (#951). Escape state propagates across overlapping recorded cycles in a strongly connected region, including nested loops with the call and escape in different inner/outer cycles. A stash after a finished loop cannot make that loop's earlier calls opaque. The proof revisits affected regions as stash addresses are discovered, spending the same allowance, and deduplicates writer evidence without dropping previously discovered sources on a budget cut. Scalar loads at variable local-buffer indexes retain the index's input origins and caller ascent alongside buffer provenance. A copied base pointer is followed using the LOAD's actual byte demand **and input memory epoch**, not a second unknown-region consumption or the later sink epoch; an unknown index still leaves coverage unresolved.

Memory-backed scalar reads use one canonical byte demand: the pointer base's must-offset plus the read's explicit STRUCT-member displacement, exactly once, at that read's input epoch. Plain pointer LOADs and named aliased local/field reads use the equivalent geometry. Copied bases carry this same demand; index provenance remains separate. Unknown member displacement or scalar width stays unknown, never offset zero or an empty read. Initializing one member cannot certify another, while a fully initialized consumed member does not require unrelated fields.

Reaching-writer provenance uses the same effective read/write member geometry: `p->b = 1` cannot become the producer of `p->a`, and a disjoint later member write does not replace an earlier source. Plain, STRUCT and supported named-object operations retain their explicit positions and actual input epochs. The sibling forward memory correlation also uses these positions: an untainted disjoint member cannot strong-kill a tainted field. Indirect pointer-slot correlation and descriptor-array field keys include the member displacement; an overlapping pointer-slot/base-pointer write blocks identity reuse, while a proven disjoint write does not. This geometry normalization preserves the existing may-provenance/taint semantics; it does not replace them with the local all-path must proof.

Scalar/NUL certainty accepts integer/pointer literals and verified byte-bit-pattern evidence, not numeric coercion of floating constants: `int(0.998)` does not describe the bytes of a floating store. Direct FLOAT_CONST evaluation is unsupported; a lifted integer zero or verified literal NUL retains its existing proof.

A reloaded stash proves a **must-offset** only when every reaching memory-PHI arm supplies the same definite local offset through an exact, value-preserving pointer STORE/LOAD identity: both widths must equal the known target pointer width (4 or 8 bytes), and their start positions must agree, including explicit STRUCT-member offsets. Slot identities retain the SSA value epoch; a parameter or PHI-defined slot address is not interchangeable with another version of the same variable. Different unresolved pointer keys or overlapping stack-object aliases do not prove disjoint memory. Covering a narrow/subfield LOAD with a larger store is not pointer identity. Narrowing, extensions, field-value reads and unsupported conversions/operators cannot restore a full pointer proof; slot-address matching also rejects lossy transformations. An entry path, unknown/partial-overlap store, opaque call or disagreeing value prevents that proof. An active backedge alone supplies no stored value, and re-entering an active stash-value query yields an unknown offset rather than repeatedly spending the allowance. This all-path query is separate from unchanged may-reaching writer provenance. Every address-expression STORE uses the same strict must-offset path for byte initialization, NUL establishment and prefix proofs, even when a may-location descriptor keys it to the buffer; named local-object writes use fixed storage plus their explicit field displacement. Definite fill bounds/values and literal-NUL evidence also reject erased conversions. Must-offset memory expansion and strongly connected escape propagation share the region proof's work allowance; standalone offset queries are bounded and return unknown on exhaustion. This is conservative identity checking, not a general bit-vector solver.

These certainty guarantees are about the **lifted model**, not independent validation of machine-code fidelity. Known Binary Ninja limitation [#954](https://github.com/m4ul3r/bn/issues/954): an x86-64 address-size override can be erased from MLIL, turning a truncated-pointer store into an apparent named `buf[0]` write. The engine cannot recover semantics absent from its input; the repaired explicit-cast STORE path must not be credited with fixing that distinct lifter boundary. Confirm address/access widths against disassembly before turning a complete modeled slice into a machine-level safety claim.

Likewise, a slice reaching an `entry` origin for a non-memory SSA field describes provenance to that entry value; it is not an initialization proof for the field. That unchanged convention is distinct from the canonical memory-read geometry above. An optimized compiler/lifter shape that removes the memory-backed read must not be credited with exercising its coverage proof.

Static tokenizer state is discovered monotonically by initializer callsite. An unused-return `strtok(buf, ...)` forces another fixpoint pass, so a continuation earlier in IL order can be reached without multiple initializers oscillating. Clean non-NULL calls, including resolved imports, kill state only on every path to the continuation/return. Unfollowed cross-function continuations retain `tokenizer_state_escapes`; an exhausted iteration budget still withholds all-clear.

Use `--models FILE` for a known wrapper; keys are current symbol names (including `sub_*` on stripped targets), never addresses, and entries nest `sink` or `sources`. For `app_recv(fd, len, buf)`, `{"app_recv":{"sink":{"class":"overflow_len","len_arg":1,"buf_arg":2}}}` models a bounded-write sink; `{"app_recv":{"sources":[{"to":"*arg:2"},{"to":"ret"}]}}` seeds its output buffer and return. `sources` is a list of `to` rules: `*arg:N` means the pointed-to buffer, `arg:N` its value, and `ret` the return. An entry that puts the sink-arming fields (`class`, `tainted_args`, `len_arg`, `buf_arg`) beside the symbol with no `sink` under it, declares no recognized role at all, or declares a role with nothing in it (`"sources": []`, `"propagates": []`, a `varargs` without `to`) is refused with the expected shape named; annotation keys beside a real role are left alone.

Overlay rules are the same for `taint models --models` and `taint forward/backward --models`:

- An **annotation-only** entry (`return_bound`, `arity_capped`, `destinations_unmodeled`, with no flow role) merges only into an existing **flow-bearing** model of the same name, preserving its flow roles. For example, `{"read":{"return_bound":{"max_from_arg":2}}}` keeps the builtin `read` buffer-source, return-source, and sink roles.
- An entry with **any flow role** — `sources`, `sink`, `propagates`, `writes`, `varargs`, or `continuation` — **replaces the entire model entry**, even when it also supplies annotations. Omitted roles are not inherited.
- A benign `{}` builtin such as `puts` is **not annotatable**: an annotation-only entry for it is refused, just as for a name with no existing model. To model flow, supply the flow role explicitly. Supplying `{}` instead replaces the entry with a benign marker.

For example, this mixed flow/annotation overlay replaces `read`; it keeps only the declared return source and return bound, dropping the builtin buffer source (`*arg:1`) and sink:

```json
{"read": {"return_bound": {"max_from_arg": 2}, "sources": [{"to": "ret"}]}}
```

The `models:` header counts only entries that carry a role; an empty `{}` or a `_comment`-only entry (a benign function that neither sources, propagates nor sinks taint) is reported separately as `benign`. `bn taint models` lists a `writes` role (`bzero`) under propagators as `literal->*arg:N`.

Backward region contracts are optional model annotations, also exposed on JSON catalog rows. `consumes: [{"arg": 1, "kind": "bytes", "len_arg": 2}]` describes a byte consumer; `kind: "cstring"` describes consumption through NUL. Each argument may have **at most one** `consumes` declaration: duplicates, including identical duplicates, are refused in full models and annotation-only overlays rather than choosing by list order. `kind: "bounded_cstring"` requires `len_arg` and reads through NUL **or** up to that byte count, whichever comes first (`strncpy`/`strncat` sources, including modeled builtin and fortified spellings). Each incoming memory-PHI arm must independently prove a string or the bounded byte range: a short terminated string on one arm and four initialized nonterminated bytes on another suffice for a four-byte bounded read. An uninitialized gap on either arm does not. Later writes transform each arm's proof before the all-path decision; appends still require an initialized destination. Cyclic proofs have the limits described above; memory-chain exhaustion withholds completeness rather than waiving coverage. Resolved imports and pinned calls use their resolved consumer contracts; disagreeing multi-target contracts remain unknown.

`initializes` promises a definite write on return: byte regions require `len_arg`, while bounded string producers require a positive constant `len_arg` and establish only the string at the destination start, not the full capacity. Byte initializers can additionally declare **one** of `zero: true`, `value_arg: N` (fill byte), or `copy_arg: N` (byte-preserving copy, enabling verified literal-NUL coverage). `preserves_cstring: true` describes appends that preserve an already initialized string, never a missing prefix.

`write_bounds: [{"arg": 1, "kind": "bytes", "len_arg": 2}]` limits possible writes through that argument to at most the count, starting at its passed pointer. It proves **no initialization** and is separate from both `initializes` and the scalar `return_bound` annotation. A zero count or a range missing a known terminator can preserve an earlier string proof. Unknown bounds cannot certify disjointness. All region annotations are validated and annotation-only overlays merge into an existing flow model without replacing its provenance rules; an unknown model cannot be created by annotations alone. Do not annotate a return-dependent receive API as a definite initializer. Unannotated/unknown extents, format-dependent vararg reads, and returned-pointer offsets not proved by an alias contract remain conservative.

`return_alias: N` additionally promises that the returned pointer equals argument N, preserving the consumed offset through calls such as `strcpy` and `memcpy`. A propagation rule alone is not that promise: `strchr`, `stpcpy` and `mempcpy` can return an interior/end pointer, so their returned offsets remain unknown. Like the region annotations, `return_alias` supplements rather than replaces the model's flow rules.

## Caller-static mapping

`bn callsites` returns native `call_addr` and post-call `caller_static` (the return address). Prefer it over hand-written `py exec` for exact caller mapping:

```bash
bn callsites parse_record --within process_message --caller-static
bn callsites parse_record --within-file /tmp/callers.txt --format json
```

`--within-file` accepts one function identifier per non-empty line, with `#` comments. A null `hlil_statement` means BN could not localize a safe statement; JSON may include a bounded `decompile_excerpt` for context. The excerpt is built for the requested page, so use `--limit` to bound its cost. Caller enumeration can stop at its budget; a short list with `caller_scan_truncated: true` is not proof that other callers do not exist.
