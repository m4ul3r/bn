# bn reference — reading

Read-command catalog for the `bn` skill. Open when surveying/decompiling. See `../SKILL.md` for the map.
## Commands

```bash
bn target info
bn target list [--format json]                       # open targets + their selectors; `selector` is what -t takes
bn function list [--count] [--min-address 0x401000 --max-address 0x40ffff]
bn function list [--sort {address|size|name}] [--reverse] [--min-size 64] [--mangled]
bn function list [--named | --unnamed]               # meaningful names vs BN's auto sub_* (import thunks in neither)
bn function search attachment [--count]              # --count here = MATCHES, not the whole-binary total
bn function search --regex 'attach|detach|follow'
bn function search <q> [--sort … --reverse --min-size N --mangled]
bn function info <fn> [--verbose] [--blocks]         # --blocks: basic-block address ranges + edges
bn decompile <fn> [<fn> …] [--addresses] [--lines 40:80] [--force-analysis] [--include-annotations] [--explain]
bn il <fn> [--view {hlil|mlil|llil}] [--ssa]          # --level is an accepted alias for --view
bn disasm <fn> [--lines 40:80 | --count 20]
bn disasm <addr> --linear [N]                        # up to N (default 32) units: one physical instruction or one undecodable .byte byte
bn xrefs <fn-or-addr> [--limit 20]
bn xrefs --field <Struct.field>
bn callsites <callee> --within <fn>
bn callsites <callee> --within-file <path>
bn evidence function <fn> [--context 2]              # per-call ABI args (LLIL/MLIL/HLIL + raw disasm) + thunk detection
bn evidence xrefs <fn-or-addr> [--limit N]           # inbound refs annotated with section/segment/symbol/disasm
bn evidence table <addr> [--entries N] [--stride N]  # interpret memory as a pointer/vtable table (Thumb-normalized)
bn evidence table <addr> --decode relative-int32 --base <addr> [--entries N]  # signed 32-bit offsets + explicit base
bn evidence table <addr> --record-size N --ptr-fields o1,o2  # mixed-record mode: scalar + pointer fields per record
bn evidence table <addr> --record-size N --field cmd:u32@0 --field name:char[16]@8   # typed scalar/string fields
bn evidence calls <reg-fn> --arg-struct N --field type:u8@2 --field cb:ptr@16  # stack-descriptor fields per callsite
bn evidence message <type-string> [--limit N]        # protobuf/RTTI type-name -> xrefs -> nearby metadata table windows
bn evidence init [--limit N]                         # .init_array/.ctors constructor-pointer summary
bn evidence orient                                   # one-shot triage digest under a single read lock: target + analysis state, imports, strings sample, sections
bn evidence surface                                  # hidden code surface: init/ctor + vtable/dispatch tables + data- or code-referenced code BN missed
bn evidence virtual-call --at <addr> [--providers <selector>]   # resolve an imported abstract/interface virtual call to the provider's vtable method
bn trace <fn> <addr> [--arg N] [--interprocedural]   # backward SSA slice: trace where a call argument originates
bn dataflow defuse <fn> --var <name|local_id|name#version>   # SSA def site + use sites of one variable
                                                    # a use that is argument set-up for a call whose
                                                    # recovered model dropped its stack-passed args is
                                                    # reported as a `hint: call ... call-model truncation`
bn dataflow callgraph <fn> [--direction {callees|callers|both}]   # resolved edges; indirect targets via value-set
bn dataflow values <fn> --at 0x401234                # value-set (possible values) at an instruction
bn taint models [--role {source|sink|propagator}] [--class overflow_len] [--present] [--callsites [--all-sites]] [--mangled]   # known sources/sinks; --present needs a target; --callsites lists real calls by application callers (stub/inline rows counted, shown with --all-sites), named by demangled caller unless --mangled
bn taint forward -f <fn> --source param:0 [--sink-class recv_overflow]   # untrusted data source→sink across calls (methodology → the `bn-vr` skill)
bn taint backward -f <fn> --sink arg:memcpy:2         # slice a sink's args back to their origin (`bounded: true` = provably bounded)
bn function cfg <fn> [--view {asm|mlil|hlil}]        # basic-block graph: blocks, their instructions, and the typed edges between them
bn function structured-il <fn>                       # flat per-instruction list: op plus vars_read/vars_written, no block partitioning
bn proto get <fn>
bn local list <fn>
bn local list --frame <fn>                           # stack frame map: one row per distinct stack offset, saved-register/canary markers, bytes to the canary
bn data vars --start <addr> --end <addr>             # typed data variables in an address window (the window is mandatory)
bn data symbols [--limit N] [--offset N]             # named DataSymbols, internal ones included (paged: 100 by default)
bn read 0x... --length N [--encoding {hex|bytes}]   # address is positional; --address 0x... is an accepted alias
bn types [--query <q>]
bn types show <name>
bn struct show <name>                                 # a struct BN records bases for (e.g. from debug info) shows `: Base` and inherited fields tagged `[from Base]` (JSON: `bases`, `inherited_members`); `types declare` records none yet (#965)
bn class list [--all] [--no-stl] [--query <substr>]   # C++ classes from demangled symbols + RTTI (+ your own declared class types under --all)
bn class show <Name>                                  # one class: methods, vtable, size, bases, instances; falls back to a class type you declared
bn strings [--query <q>] [--regex] [--min-length 5] [--section .rodata] [--no-crt] [--with-xrefs]
bn imports [--summary]                                # rows carry `library` from ELF symbol versions; DT_NEEDED is in `target info`
bn exports [--count]                                 # global/weak definitions from any symbol table, not loader-visible exports
bn go functions [--summary | --count]                # recover Go names from .gopclntab (then `bn go rename`, a mutation)
bn sections [--query <q>]
bn tag list [--type Bookmarks --query <substr>]      # tags at all scopes; `--type Bookmarks` is the bookmarks tag
                                                     # UNFILTERED it walks EVERY function (function tags + address tags);
                                                     # narrow with --function <fn>, or --data for data tags alone
bn tag get 0x401000                                # tags at one address
bn tag get --function <fn>                          # whole-function tags
bn tag types                                         # tag types (built-in + custom)
bn comment list [--query <q>] [--scope {all|address|function}]   # `all` (default) includes function docs
bn comment get --address 0x...                     # address comment
bn comment get --function <fn>                     # function documentation comment
bn bundle function <fn> [--out bundle.json]          # export; does not mutate the BNDB
```

`dataflow values` keeps the instruction/assignment-source set in `possible_values`,
with `value_basis` identifying which expression supplied it. For a call or tail
call, `call_destination` separately reports the destination `expression`,
`value_basis: "destination_expression"` and its own `possible_values`. Destination
addresses are not possible return values. Unknown destinations remain unknown;
the destination set does not replace a determined instruction value or change
assignment-source selection.


Notes:

- `function search` is a case-insensitive substring search over the demangled display name. Use `--exact` for a known API, `--word` for an identifier token, or an anchored `--regex` for a family. A regex-shaped zero-hit literal query may be retried as a regex; `regex_fallback` discloses that choice. Confirm a source or sink against the import and actual call target, not its name alone.
- **Names in text are demangled.** `function list/search/info`, `xrefs`, `callsites`, `comment list`, `exports`, `strings --with-xrefs`, `taint forward/backward` (header, flow and slice sinks, slice origins, signatures, frontier callees) and `trace` (header, call boundaries, out-param fills, crossed functions, frontier roll-up) print the demangled display name (`demo::Widget::handle`), the spelling `decompile` and `class show` use, and any of them resolves as an identifier; where overloads share one display name in a `strings --with-xrefs` list, each carries its address. JSON keeps the raw `name` (mangled for C++) beside `display_name` (`function_display_name` on `comment list`, `xrefs --field` rows and `trace`; `callee_display_name` on a taint `sink`, a `trace` step and `trace`'s `arg_label`; `origin_callee_display_name` on a backward slice; `out_param_callee_display_name` on a `trace` out-param step; `signature.rendered_display` beside the raw grouping key `signature.rendered`). A taint `sink.callee` is the model key, which drops a symbol's leading underscores (`strcpy_chk`, `ZNSt13basic_filebuf…`); `sink.callee_symbol` is the real symbol (`__strcpy_chk`), `signature.rendered_symbol` spells the signature with real symbols, and a C sink's display name is its real symbol. `--mangled` prints raw names instead (real symbols for a taint sink and its signature); on `function search` it also matches raw names, and a default search whose query only a mangled name contains reports `mangled_only_matches`. Free-text caveats and notes keep raw names. The old `--demangle` is still accepted and changes nothing.
- `function list --count` counts all functions; `function search <query> --count` counts matches. `--sort size --reverse --min-size N` is useful for large functions. `--sort name` orders by the name the text shows: the demangled display name, or the raw name under `--mangled`. `--named` / `--unnamed` separate meaningful names from auto `sub_*` names.
- `exports` lists global/weak function and data definitions from any symbol table in BN's combined symbols; `exports list` is an alias, and `--count` counts that same population. It does **not** establish dynamic-loader visibility. On ELF, a global definition may exist only in `.symtab`, not `.dynsym`; use `readelf --dyn-syms` or `nm -D --defined-only` to inspect the dynamic table instead. The synthetic ELF case reported in [#921](https://github.com/m4ul3r/bn/issues/921) had 235 definitions under `bn exports --count` but only 2 under `nm -D --defined-only`: those are different populations, not evidence that all 235 are dynamically exported.
- **Duplicate function start addresses are disclosed (#757).** Binary Ninja can hold more than one Function record for one start address. Where an answer holds such an address it publishes `duplicate_starts_collapsed` / `duplicate_starts_unresolved`, and every text face that answer reaches discloses it too. This entry states no more than that on purpose: every summary of what the collapse does to a given answer has been false on some shape of it, so the answer carries that truth and this page does not restate it.
- `evidence orient` text prints every returned string row and section name; `--strings-limit` bounds the sample, and the header names how many candidate strings the min-length / data-section filter dropped (`filtered`).
- When the `evidence orient` strings sample is truncated, its text prints a runnable `bn evidence orient --strings-limit N` command to request the full sampled population; append the same `-i` / `-t` routing options if needed.
- `evidence function` uses display names in its header and target lines by default, and raw names for both with `--mangled`; JSON retains both names. This is deliberately not a universal name-rewriting flag: decompile warning prose, `class show` thunk target labels, and `evidence table` / `evidence init` pointer targets retain raw symbol names (#1006). Raw labels distinguish ABI entries such as D1/D0 destructors whose display names collide.
- `evidence orient` reports `existing_annotations` at the top level. A restored `.bndb` can carry earlier names and comments. `decompile` omits stored annotation bodies by default; `--include-annotations` opts in. Redaction covers matching standalone or inline `//` annotation lines, not arbitrary block comments or differently rendered text. Use `--addresses` when mapping a rendered line back to code.
  - A comment this bridge wrote and verified (`bn comment set`, `--function`, or `batch apply`) is not redacted: it renders as `// [this session] <body>`. Its location and body must both match; a body also stored somewhere else stays redacted. `py exec` writes do not count. Text mode ends with `note: N stored comment line(s) hidden as <annotation redacted>`, and JSON `annotation_summary` carries `hidden` and `session_shown`.
- `strings` ranks a dump by the section a string sits in: `.rodata`-like (ReadOnlyData) first, `.data`-like next, then code bytes that decode as text and linker metadata, in address order within each tier; where sections overlap the narrowest claiming one decides. An address no section claims is noise only when the view has a ReadOnlyCode section and the address is in an executable segment; on a raw image or a section-header-stripped ELF (BN adds only `.synthetic_builtins`) nothing is ranked and the dump is plain address order. `noise_strings` / `noise_sections` name the last tier and `data_sections` the data sections the listing drew on; the text tip names them only when noise is non-empty, recommends `--section <top data section>` only on an unfiltered dump, and `--section` pins one section in address order. `evidence orient` samples only the first two tiers (`sample_sections` says which, in sampled order) and names the fallback in `sample_fallback` when a view has no strings there.
- `bn decompile handle parse_file main` uses one bridge call and preserves the requested order. A missing identifier keeps its row and makes the command exit 2. One identifier retains the single-function `.text` shape; several return `{"kind": "decompile_batch", "requested": 3, "resolved": 2, "functions": [...]}`. Read `.functions[].decompiled.text`, not `.items[]`. An `analysis_skipped` stub is not a body; `--force-analysis` analyzes that function and can be slow.
- `proto get` prints the display name on its text prototype line; `--mangled` selects the raw symbol name. Display names are descriptive, not necessarily valid C declarators. JSON `function` carries `name`, `raw_name` and `display_name`. `implicit_object_note` is neutral current-state reporting: the first parameter's current name and type (or the absence of parameters), beside the available observation that BN's demangled signature describes a leading object parameter. It does not say who supplied the name/type, attribute recovery, infer parameter correspondence or verify an ABI. Function-level user-type and per-variable user-definition flags are not used to infer provenance. For `proto set`, BN's parser rejects a parameter named `this`; the refusal recommends `self` or a free numbered variant if that name is already used. Apply the exact suggested spelling. Named function types such as `ns::Callback` retain named-type resolution. Nested backticked template types are passed to BN's parser; a parser or fallback refusal is a clean `invalid_request`, not an internal exception.
- `decompile` can disclose a **struct layout candidate** in `.warnings` (text mode prints its one-line summary; `--explain` prints the full note) for an incoming `void *` parameter. The witness is direct MLIL-SSA loads/stores at two or more distinct constant byte offsets, all matching complete flat scalar members' offsets and widths in exactly one compared struct layout. Every other use of the incoming pointer value except a comparison (a copy into another variable, a PHI, a derived pointer, a call argument, a stored value, or a taken address) disqualifies the parameter, because accesses through that value would escape the witness. The note names the parameter, layout, fields, and access widths, and states that layouts holding the offsets in nested, union, array, or base-class members were not compared; it is evidence of layout compatibility, **not recovered type identity**. Review with `struct show` and `disasm`, then use `proto get` and explicitly apply the full edited prototype with `proto set`, preserving the other parameters, qualifiers, and calling convention. For example, if the current prototype is `uint64_t handle(void *c)` and the candidate is confirmed, use `bn proto set handle 'uint64_t handle(struct cfg *c)'`.
  - This assistance never applies a type or changes the rendered body on read; already-typed pointers keep their existing rendering. Batch decompilation carries the same per-function warnings.
  - Known layouts include loader-provided and other auto-defined structs already in the view, not only user declarations. A missing analyst-defined type does not mean no compatible layout exists; adding it can make an existing match ambiguous.
  - Named scalar member types are resolved through up to 16 typedef references before matching, only for members at an observed offset and width, with exactly one view type lookup per hop (by ID, or by qualified name when no ID is present). The shared resolver used by `struct show` and class declaration reads enforces the same lookup budget and detects cycles by reference identity, not Python wrapper identity. An unresolved ID is not retried by name. Unresolved, cyclic, or longer chains and non-scalar terminal types do not supply a member witness. Distinct concrete structs remain distinct candidates even when their members differ only in typedef spelling; aliases of a whole struct do not add candidates.
  - Matching distinguishes a positive scalar witness, an excluded layout, and an unclassifiable member. An unresolved, cyclic, or over-budget member at a matching offset and width, or an access overlapping a bitfield's storage unit, overlapping members, or the span from a zero-width member (an unresolved named type or flexible array) to the end of its layout, cannot supply a hint, but an otherwise compatible flat layout containing it blocks any claim of a unique candidate. A trailing flexible array covers no bytes. A base-less `class` layout, and a layout whose members overrun its recorded width (for example after redeclaring an embedded type), are compared like a struct and block uniqueness when compatible, but are never themselves suggested. A layout whose flat scalar members do not match an observed offset/width, or whose observed member is non-scalar, is excluded from the comparison; that is a scope limit, not proof that it cannot be the parameter's type. Opaque types elsewhere in the view, including unobserved members and bitfields away from every access, do not by themselves suppress hints.
  - Scope is deliberately narrow: no pointer-alias/dataflow recovery, computed indexes, reassigned pointer values, class suggestions, or comparison of accesses that land inside a nested struct, union, array, or base-class member. Such layouts can be compatible yet neither block nor appear, which the warning discloses. Conflicting widths/offsets or multiple matching layouts produce no suggestion. A missing hint is **not** proof that no struct could fit, and a hint is **not** proof that no other type fits.
- `decompile` JSON keeps `warnings` as a list of sentences, the same shape `il`, `bundle` and `evidence` use, and adds `warning_rows`: the same warnings in the same order as `{code, summary, detail, address}` plus structured facts (`calls`, `addresses`, `types`, ...). `address` is the first reported site for a grouped warning, or the function entry for a function-wide warning; grouped site lists remain complete. Each `detail` is the matching `warnings` sentence. Text prints one `warning[<code>]: <summary>` line each; `--explain` adds the detail (what it means, what to do) under each. Filter on the code, not on `^warning`: dropping every warning also drops the dropped-argument findings. Codes: `arity`, `jump`, `branch`, `offset`, `select`, `layout`, `split`, `callee_split`, `fragment`, `string`, `stub`, `thunk`, `forced_data`. A `/* bn: ... */` comment on a Pseudo-C line (after the code, before any `//` comment) is bn's note, not Binary Ninja's; a `❓` line is control flow Binary Ninja could not resolve.
- Beyond struct layout candidates, `decompile` warns about these ways the Pseudo-C can mislead:
  - **call arity** (`arity`): a call rendered with fewer arguments than the call site passes. This happens when BN's prototype for a library callee is too short; type libraries often leave out `this` and trailing parameters (`std::filebuf::open(&f)` for `open(&f, path, mode)`). The warning is backed by the demangled signature of a mangled callee, or, for an import, by the argument registers written since the previous call and read by nothing else (a `csel` that computes an argument right before the call counts; registers only its comparison reads do not). It also covers a mangled callee rendered with *more* arguments than its signature takes. The call line itself carries `/* bn: +2 args not rendered: x1 = [sp].q, x2 = 0x30 */`, naming each dropped register and, when it is known, its value: a constant, a parameter name (cast when only its low bits were copied: `(uint32_t)arg2`), or the register-level source. A register overwritten before the call -- by any write, including a split pair or an intrinsic such as `mrs` -- is never shown as a value; a bare register name means unknown. JSON `calls[]` has one row per call. Sized `operator delete(void*, size_t)` is not reported: BN always drops its size, which is allocator bookkeeping. Read the real arguments with `bn callsites <callee> --within <fn> --context 4`.
  - **unresolved jump** (`jump`): an indirect jump with no target BN resolved and no successor block, rendered `❓ /* jump -> <expr> */`. The `❓` marks control flow Binary Ninja could not resolve. There is one row per machine jump, even when BN repeats it in several switch cases, and every line that shows a copy carries `/* bn: unresolved jump: a tail call (args not rendered) or a computed goto */`. The row names the target expression and both readings, and claims neither: a tail call through a pointer, leaving the function, whose arguments are in the argument registers at the jump and are not rendered (read them in `disasm`; type the callee with `proto set`, or the object the pointer is loaded from, so BN renders the call), or a computed goto or jump table BN did not follow, staying in the function, whose code may not be part of the function's decompile or disassembly. No step is sure to find those targets. When the target expression reads a data address (`table` in the row), `xrefs <table>` lists the code that reads and writes it -- references to the base address only, so a store to a later entry may be missing; for a table filled at run time (a `.bss` table) the writes are where the target addresses are stored -- and `evidence table <table>` reads its current bytes, which name targets only for a static table (absolute pointers, or with `--stride 4 --width 4` 4-byte signed offsets added to the table base; a run-time table reads as zeros). Stores in the decompile that write code or table addresses into what the jump reads may name them too; a table a store names is read with `evidence table <address>`. For a `data_<hex>` placeholder, use its hexadecimal address; resolve a symbol with `xrefs <symbol>` and read the address in its header. Read a target address's code with `disasm <target> --linear 16`. With `--explain` the detail is wrapped into short lines, each backticked command kept whole. Import stubs and the PLT header are skipped. Telling the two readings apart is not attempted.
  - **resolved indirect branch** (`branch`): reports only targets in BN's own indirect-branch records, including any target addresses BN models as separate function starts. `targets[].function` names those separate bodies; read them with `decompile <address>`. This does not recover missing table entries, establish that all destinations are known, or classify a branch as a computed goto or tail call.
  - **`__offset(T, N)`** (`offset`): BN's spelling for a pointer N bytes into an object of type T. The warning looks T up the way `types show` does (by the rendered qualified name, so `std::_Rb_tree_node_base` and template names are found): it names the ones defined in the view, and calls the others what they usually are, named references BN made from a symbol or demangled signature with no layout (so `types show` will not find them; create one with `types declare`). A `vtable_for_C` base is C's vtable object; `+2 * pointer size` is its address point, a vptr value. The entire summary is capped at 240 characters, listing whole names only and counts for omitted names. JSON and `--explain` keep all names.
  - **split body**: a block that runs straight into another function's entry without a branch, or a prototype whose parameters sit in callee-saved/link registers (`arg3 @ x19`, `arg5 @ fp`). Both usually mean BN split the body at a shared tail. Callers of such a function get a `callee ... takes parameters in callee-saved/link registers` warning, `proto get` prints the same notes, and `disasm` prints `// falls through into <fn>` right after the instruction that runs into it. The `proto set` advice is given only for a function something calls, directly or through a data reference (a vtable slot or function-pointer table); a piece entered only by jumps or fall-through is told its registers are live-ins, not arguments. No mutation merges or extends function bounds.
  - **EH/cold fragment**: an unnamed exception-cleanup (landing pad) or cold-path piece BN made a function of its own gets one note instead: its callee-saved-register parameters are its parent's live registers, not a split to repair. A fragment has an `_Unwind_Exception` parameter or a `.cold` name, is never called nor address-taken and either never returns or has no references at all, or never returns and is called only by other fragments.
  - **raw string pointer** (`string`): a call argument rendered as a bare address (`0x400b90`) that holds a NUL-terminated string BN never defined, so `strings` does not list it either. It needs at least three printable bytes, or a callee that takes a narrow `char *` there: by its prototype, its demangled signature, or, for an import or a prototype that stops short, its C library name (a built-in list checked against glibc plus the format argument of the printf/scanf family, else the platform type library's prototype: `strcmp(arg, 0x661bd8)` names `"C"` even when `strcmp` is untyped). BN's placeholder `&data_400b90` counts only with that `char *` evidence, since BN gave the address a data variable that may be an `int[]` or a struct (`setlocale(6, &data_400b90)` is named; `memcmp(p, &data_…, 16)` is not). A prototype applied with `proto set` is never overridden by the name lookup. Shorter runs passed elsewhere are too often an `int[]`, UTF-16 text or a struct. Opt in to defining it with the `bn data retype <addr> 'char[N]'` command the warning prints.
- `disasm --lines START:END` and `--count N` count rendered function rows, not bytes. `disasm <addr> --linear N` walks physical instructions and undecodable `.byte` units outside recovered blocks. For width, branch, or bounds claims, inspect the instruction operands. On Thumb, include the preceding `IT` instruction and every covered instruction.
- `class list` groups demangled C++ methods and RTTI. Its default favors RTTI/constructor-supported classes; `--all` also shows name-only and user-declared class/struct/union types. A name-only cluster may be a namespace; a declared-only card does not prove methods or vtables are absent. One class demangled under two spellings (`Holder<std::string>` and its `basic_string` expansion) is one card, reachable by either through `class show` and `--query` alike; the other spellings are `aliases`. `class show` reports ambiguity and scan caps rather than choosing a same-leaf class or treating a truncated vtable as complete. A vtable ends at the next object (an RTTI record or vtable BN names at that address, or a typeinfo's vptr), never inside it; BN's own `VTable` width is reported as `bn_vtable_slots` but never bounds the walk, because BN stops that struct at the first null word and an abstract class's zeroed destructor entries sit mid-table. An imported class's typeinfo is an import slot: `bases` is empty with a note, not decoded from GOT words. A `secondary vtable` recovered by typeinfo backwalk is `[rtti]` when its slots are this class's `_ZThn<N>_` thunks at that offset-to-top or BN's own `vtable for X{for `Y'}` symbol names it, else `[heuristic]`; a candidate whose word[0] is a mapped pointer or out of bound is listed under `rejected_secondary_candidates` with the observed reason. Confirm a `[heuristic]` secondary with `evidence table` before reporting an inheritance edge.
- For returned-page RTTI-backed records without a vtable symbol, `class list` tries the same primary typeinfo backwalk as `class show`, even after methods are named, sharing a fixed 50 ms monotonic budget across the page. Recovered rows carry `vtable_status: "recovered"` and `vtable_slot_count` (`slots=N` in text); `method_count` still counts clustered methods, not table entries. A capped table has an unknown slot count. Budget exhaustion is explicit in text and `vtable_recovery_budget_exhausted`; unchecked rows have `has_vtable: null`, not a false `no-vtable`. Missing/raising optional APIs, failed or short raw reads, unreadable slot rows, and imported RTTI leave that row unknown with `vtable_status: "unavailable"` and a null slot count, without aborting the page. Imported RTTI does not establish an empty table in another module. `--count` skips recovery.
- A decoded vtable's `address` is the Itanium object head; slot zero is at `address + 2 * pointer_size`. In stripped binaries BN may synthesize `vtable for X` on slot zero instead. The class lens normalizes that address only after reading a preceding zero offset-to-top, local typeinfo for the same class, and fully resolved nonvirtual RTTI ancestry; it does not move BN's symbol. ABI selector provenance first checks the object head two words before the typeinfo vptr, so an adjacent unrelated extern at the exact vptr cannot override it. Virtual-base ancestry (including inherited virtual bases), imported/unresolved bases, unreadable base records, or an unknown ABI RTTI selector leave the original address and conservative `no_local_vtable_body`: construction tables share the same header, even when there is only one candidate. An existing object head is kept, import/GOT aliases are not normalized, and a nonzero-offset candidate remains the secondary backwalk's responsibility, never promoted to a primary. Stored-global instance lookup uses this proven slot-zero address point for decoded layouts, including capped or unreadable slot scans. An undecoded entry or `no_local_vtable_body` does not authorize adding two pointers: lookup keeps the original symbol address. Named VTT and construction-table objects are excluded only within BN's proven data-object width; without a width, only their first word has proven ownership. Consecutive address-point pointers and the next symbol do not prove an untyped VTT's extent: an unnamed neighboring object can have the same vptr. Remaining references are preserved with a note that they may include untyped ABI entries; stored-global totals count references, not proven instances. Unnamed ABI containers are not identified.
- `class show`'s vtable (and each secondary) also carries `address_point`, slot zero: the vptr value objects store, so `xrefs` on it finds the constructors that stamp it, while `xrefs` on `address` usually finds nothing. Text prints `vtable @ <address>, address point <address_point>`.
- `callsites` reports data locations holding the callee's address separately from recovered calls. For locations inside a defined ELF `_ZTV` object's symbol extent, its note prints `bn class show -- <class>` only when that full canonical name uniquely selects the same object in the current class registry. JSON adds `callee_data_ref_vtables` with `evidence: "elf_symbol_size"`; extents are mapped using BN's image-base metadata, not nearest-symbol guesses. Anonymous/stripped tables, ambiguous or noncanonical names, mismatched symbols, and unsupported/budgeted proof surfaces fall back to `bn xrefs <data-location>`. Neither hint promises a list of virtual callers; `class show` still accepts names, not table addresses.
  The primary address point is read from a zero offset-to-top and same-class local typeinfo header within the first 64 words of that object; virtual-base offset prefixes are not mistaken for the header. An unseen or ambiguous header leaves `address_point: null` and the note says it was not decoded, while retaining the known class-layout command.
  Attribution requires a complete supported identity census: any capped, malformed or unread symbol/string table discards all class hints, including earlier matches from another table. Invalid ordinary section indexes and `SHN_XINDEX` refuse attribution; the helper deliberately does not decode extended indexes, even with a companion `SHT_SYMTAB_SHNDX` table. Every defined `_ZTV` must have a supported object type, positive body extent and valid file-backed owner; zero-size/short aliases, NOTYPE, absolute/common, or unresolved owner/bounds refuse attribution rather than disappearing. Undefined imports are known non-definitions. Relevant local definitions are selected among all same-raw-name symbols, not an arbitrary GOT/import alias.
  Name navigation additionally requires bounded native symbol/function populations (at most 65,536 each), no other local object under the full name, and an exact canonical class-registry record at the ELF object head. A second marker is allowed only at the header-proven primary address point, never merely because it lies inside an extent or is another ELF-defined head. When all refs are outside known extents, no per-vtable symbol/header work or registry proof runs; a positive candidate can require the existing bounded registry scan.
- Construction sites in `class show` are ordered by numeric call-site address before the display cap, so the displayed prefix is stable across bridge sessions.
- `evidence surface` surveys constructors, pointer tables, and executable addresses BN may not have made functions: those referenced from data, and those whose address code takes (an `adrp`/`add` or `lea` storing a handler into a struct field, `sa.sa_handler = handler`, shows as `&data_<addr>` in the decompile). A code-referenced candidate's `provenance` is `code_ref:<function>@<site>` and `referenced_from` lists the sites; a site that only loads from the address, computes a jump-table base, or is an aarch64 `adrp` whose consumers only add a nonzero page offset (the page base `bn xrefs` also drops), does not nominate it. It is read-only; candidate `code_likely` and `decode_depth` are triage signals, not proof. Verify a candidate with disassembly before `function create`. `evidence init` handles pointer width, endianness, and ARM/Thumb normalization. `evidence table` distinguishes pointer arrays from mixed records; declare record stride and pointer or scalar fields only when the layout is known.
- `evidence calls <reg-fn> --arg-struct N --field name:type@offset` reads a stack-built descriptor at each registration call. `ptr` resolves a callback/data symbol when possible; unknown, computed, and merged values remain marked. Confirm heuristic values at `source_address`. `evidence function` pairs calls with raw ABI and IL evidence and says how far each call's `arguments` can be trusted. Its `target:` lines print the demangled callee name (JSON keeps the raw `name` with `display_name` beside it); `--mangled` prints the raw one. `argument_confidence` is `recovered` (what HLIL recovered for a resolved callee, with no contradiction found; not a claim that it is correct), `inferred` (an HLIL list with a positive reason to doubt its arity, named on an `arity:` line or a `NOTE`), or `heuristic` (a lower-IL list or an unresolved callee). `arity_witnesses` reports each independent arity check per row: `library` (an attached type library's signature) and `callee_body` (incoming argument registers the callee's own body uses), each `agreement`, `contradiction`, `unavailable` or `refused` with a `reason` code and the counts it observed. `arity_witness_counts` tallies them over the function. Only a contradiction counts against a row; an unavailable or refused witness is evidence neither way, and `callee_body` agreement means only that the body uses no argument the prototype lacks. `evidence virtual-call` may return several providers or a typed unresolved reason; a capped scan is not absence.
- `trace <caller> <call-addr> --arg N` follows MLIL SSA backward within the caller. `--interprocedural` follows return values into internal callees; it does not map callee parameters up into callers or follow output-pointer writes. The boundary leaf is `out_param_not_followed` locally or `interprocedural_out_param_not_followed` with `--interprocedural`. A step whose value is the address of a local (`x1 = &var_68`, a stack array or struct) ends at an `address_of_local` frontier naming the local, with a caveat: `trace` does not follow the stores into it. When the traced argument itself is that address (directly or through register copies), a hint prints the `bn taint backward -f <fn> --sink arg:<callee>:<n>` that slices those stores and a `bn taint forward` for an output pointer: `--source call:<callee>` when the callee's model declares it writes that argument (`*arg:<n>`), else `--source arg:<callee>:<n>`. For an unresolved callee it prints only `bn decompile <fn address>`. Use xrefs and another trace to climb callers.
- `function cfg` contains block edges. In asm view, edge `to` values are addresses; in MLIL/HLIL they are IL instruction indexes. `data vars` requires an address window; `data symbols` lists internal DataSymbols that exports omits. These read under the shared read lock, unlike arbitrary `py exec`.
- `bn read <addr> [N]` (or `--length N`) reads mapped bytes, with a hard ceiling of 100000 bytes per request. A short mapped read sets `short_read`; a request above the ceiling sets `capped`. Either is partial, with `requested_length` and a note. `--encoding escaped` prints the bytes as a quoted C-escaped string (`\0`, `\n`, `\xHH`, one escape per byte), so the NULs between adjacent short strings stay visible. Under `--encoding bytes`, the note is visible on stderr while stdout carries the raw bytes; NULs are invisible on a terminal, so use it for redirection or `--out`. An unmapped start errors.
- `strings --min-length/--max-length` count decoded characters, not storage bytes; a row's `length` is bytes and `chars` is characters. `strings --with-xrefs` adds, per listed string, the functions that reference it (`xref_functions`, first 8, plus `xref_function_count`, `code_ref_count`, `data_ref_count`), so a filtered set such as `__func__`-style logger names maps to its users in one call. A `data_ref_count` that could not be read is `null` with a `data_ref_note`, never `0`.
- `xrefs --any` marks each probed string address with `[string]` in text (`target_kind: "string"` in JSON), distinct from function/symbol rows. Use `strings --query <text> --with-xrefs` to name its referencing functions rather than only counting them.
- `target info` states `needed_libraries` (DT_NEEDED), `soname`, `rpath` and `runpath`. An `imports` row's `library` is the library its ELF symbol version requires (`.gnu.version_r`); an unversioned import (or a target with no symbol versioning, common with musl/uClibc) stays `null`, and the listing then names the DT_NEEDED list it can come from. A dynamic-section value that is out of range for the file (a corrupt or hostile entry size, a table past the end of the file) is skipped, not guessed around, and named in `dynamic_section_notes`.

`evidence table` never guesses relative jump-table encodings. Select
`--decode relative-int32 --base <address>` to read signed 32-bit offsets in the
target's byte order and add the same explicit base to each one. The base need not
be the table start. This mode defaults to 4-byte stride and width; `--stride`
can select spaced entries, but a width other than 4 and record fields are refused.
JSON retains each raw hex `value` and adds signed integer `offset` and hex
`decoded_address`; `target` and plausibility describe that decoded address.
A zero offset points to the base, not a null pointer. Omitting `--decode` keeps
the absolute-pointer interpretation, including under `--stride 4 --width 4`.

Before an unfamiliar large read, use `--estimate-output` to measure its output without emitting the body; then slice with `--limit`, `--lines`, or `--out`.

## Data-symbol pagination cost

`data symbols` defaults to 100 rows, but **every page rebuilds the full named-symbol population**: the bridge enumerates all DataSymbols and filters out unnamed ones again to compute the honest `total`. Only row construction and serialization are limited to the requested window. There is no population cache shared between pages; walking every page repeats the full scan under the shared read lock on every request and multiplies aggregate lock-hold cost.

For an index that needs every symbol, prefer one whole-set request:

```bash
bn data symbols --offset 0 --out /tmp/bn-data-symbols.json   # omit --limit: uncapped, one request
bn data symbols --offset 0 --limit 50000 --format json     # one large page; whole set only if total <= 50000
```

`--out` removes the default page limit, but an explicit `--limit` still wins and a nonzero `--offset` still skips rows. Read the artifact named by the output envelope. Programmatic callers can send op `data_symbols` with `{"offset": 0, "limit": "all"}` for the whole set; the response echoes `limit: null`. Omitting `limit` or sending `null` instead requests the default 100-row page, not the whole set; CLI `--limit` accepts a positive integer, not `all`. A single request still pays one full population scan and builds all requested rows while holding the read lock. Check `has_more` before treating a numeric-limit result as complete.

## JSON reads and coverage

Most collections use `{kind, items, total, offset, limit, returned, has_more}`. Inspect `kind` before selecting a container. Common leaves:

| Read | Rows or payload |
|---|---|
| `strings` | `.items[].value` |
| `function list` / `function search`, `imports`, `exports` | `.items[].name`, `.items[].address` |
| `sections` | `.items[].name`, `.start`, `.end`, `.length`, `.semantics` |
| `types` | `.items[].decl`, `.layout`, and aggregate `.members[]` |
| `local list` → `.items[]` | same list retained under `.locals`; rows carry `.local_id`; stack rows carry `.distance_to_next_slot` (slot pitch, not object size; the top negative slot measures to entry-SP offset 0 even when no slot is recovered there) |
| `local list --frame` → `.items[]` | one row per distinct stack offset: `.storage`, `.kind` (`local`/`saved_register`/`canary`/`return_address`/`caller_frame`), `.names`, `.distance_to_next_slot`, `.to_canary`, `.variables[].local_id`; top level `.canary_storage`. Canary evidence requires a full-ABI-word guard load and copy; TLS identity comes from architectural registers, not mutable local names. |
| `xrefs` | `.items[]`, with `.kind` and `.caller_function` per reference |
| `callsites` | `.items[].caller_static`, `.callee`, `.containing_function` |
| `comment list` | `.items[].comment` and `.scope` (`address` or `function_doc`) |
| `tag list` | `.items[]`; `tag get` instead uses `.tags[]`; `tag types` uses `.tag_types[]` |
| `evidence function` | `.calls[]`, plus pagination metadata |

Addresses in JSON are hex STRING values such as `"0x401000"`; convert before arithmetic. `row_fields`, when present, lists available row keys. A zero-hit read may have no schema for a kind without a declared schema.

**Absence requires a complete read.** Check `has_more`, caps, and scan notes. In particular, an import xref scan may return `items: []` with `truncated: true` and `scan_note`; text prints `note: the caller scan was TRUNCATED`. That means unknown, not zero callers. For high-fan-in `callsites`, `total: null` is a lower bound: inspect `total_lower_bound`, `scan_truncated`, `caller_scan_truncated`, and `caller_scan_note`. Either truncation flag prevents a complete-caller claim. A determined integer total must remain stable across pages.

`Client.collect` and both `bn-kernel` backends report callsite coverage from the final request's cumulative scan, not the first page or a sum of page counts. The scan starts at row zero and includes lookahead, so `callers_scanned` and `total_lower_bound` need not equal the number of returned rows, especially with finite limits, nonzero offsets, or zero-row probes. An exact `total` replaces the lower bound; `total_lower_bound` is then omitted. A terminal `has_more: false` can still accompany `caller_scan_truncated: true` and `total: null`: all discovered rows were exhausted, but caller enumeration remains incomplete.

For taint JSON, forward flows are `reached_sinks[]`, each with `.sink` and `.path`; backward results are `slices[]`, while top-level `sinks` repeats the query. `sink_status[]` discloses whether a backward sink was seeded or proven `bounded`. On a zero-sink forward run, read `diagnostics.safe_to_report_all_clear`: weak seeds or unmodeled-call assumptions can withhold an all-clear even with no leaves or truncation. A true gate only supports absence of modeled sink flow under that analysis, not absence of bugs. A backward run reports `diagnostics.safe_to_report_complete_slice`; it is false whenever a frontier leaf remains, the run was truncated, or any slice `origin.kind` is `unresolved` (counted under `diagnostics.frontier.unresolved`). A slice that reaches `p = &local_buf` at any offset (`p = &line + off`, or a sink handed `&local_buf` directly) continues through every writer of the buffer on the sink's memory chain, beside the offset -- a modeled call that filled it (`snprintf`, `strcpy`, `memcpy`, a `read`-style source) to that call's operands, including a nested local buffer read at that call's own memory version (`strcpy(buf, &other[i])` walks `other`), a plain store such as a `buf[n] = 0` terminator, a store through a phi'd loop cursor built on `&buf`, a modeled call that reloads the slot `&buf` escaped into, a `memset`/`bzero` literal fill, and a length argument of a bounded fill (`memcpy(buf, lit, n)`); a parameter or source copied in by an older writer outranks a later literal append as the origin. The current coverage classifier accepts a must-alias fill or source at offset zero (subject to the guarded-length limitation below) or a whole-variable store; an indexed or constant-offset store, a copy at an offset (`strcpy(buf + 60, ..)`), a loop-only fill, an escape of `&buf`, a pointer that may point at another local, and a `{}`-modeled call cover nothing. An `address_of_local_unresolved` leaf names the buffer whenever the walk could not account for its bytes: an unmodeled call that received `&buf` or ran after `&buf` escaped to memory, a path to the sink that no writer covers, a writer input that is neither a literal nor a local (a constant address into read-only data is a literal; the address of a `.data`/`.bss` global, or an element of one at a variable offset such as `g_hosts[i]`, is a leaf with origin `global`), a store through a pointer the walk cannot resolve (a reload after `&buf` escaped), a modeled call whose out-argument pointer cannot be resolved while `&buf` is escaped, or a memory chain past the walk budget (`stats.truncated` with cause `memory_chain`). A `{}`-modeled callee handed `&buf` is named in `assumptions`: the slice trusts that it writes nothing tainted.

**Backward coverage limitation (#931):** “covered” is currently an all-entry-path memory-chain classification, not a proof of initialization of the sink's consumed byte range. The constant zero/short-fill guard applies only to length operands selected by `sink.len_arg`, or by `sink.tainted_args` for an `overflow_len`/`fortified_overflow` model, excluding operands already walked as data inputs. This includes the modeled read/recv, memset/bzero and bounded-copy families; their source and length steps remain in the slice. Source-only models without that metadata, including `fgets`, `fread` and their modeled `_chk` variants, are **not guarded** and can still report complete for zero/short requests. Wide-copy element counts use the recovered callee destination pointee width; a positive count of unknown element width cannot be classified as short. Unknown extents, short/error I/O returns, string termination and append semantics still require the full write-extent model. BN may lower `strcpy(buf, "literal")` to a short constant builtin `strncpy`; the whole-object classifier can then report incomplete even in a no-escape loop. When the bounded escape solve converges, an escape at the bottom of a loop applies to calls in subsequent iterations. LOADs consult memory-version-keyed remembered-slot sets, which fix the direct one-slot future-stash repro but are not reaching pointer values or general flow-sensitive stash provenance. An exhausted solve withholds completeness; named-frontier recovery after a discovery cut is limited to the straight-line case described below.

**Known stash-provenance limitation (pre-existing on base `5aba57ee`):** held old LOADs copied through another stash, and overwritten/restored slots, can still fabricate the source of a complete slice. For example, with `stash` initially pointing to a separate global buffer:

```c
memset(buf, 0, sizeof buf);
old = stash;                  /* old target, loaded before buf escapes */
stash = buf;
alias_slot = old;
strcpy(alias_slot, getenv("HOST"));
popen(buf, "r");
```

At O0 this can report `complete=true`, no leaves and origin `source:getenv`, even though the copy writes the old target and `buf` still comes from memset. Remembered slots are not killed by definite overwrites; `stash=buf; stash=other; strcpy(stash,host)` and restore variants have the same provenance limitation. The direct one-slot future-stash fix does not repair these cases. They occur on base, round 1 and round 2 of PR #1024 and are deferred to coordinator-filed follow-ups, not claimed fixed here.

**Known budget-cut frontier limitation (also pre-existing on base `5aba57ee`):** after a discovery cut, the bounded collection pass retains the nearby named escaped-call frontier in the tested straight-line case. It does not iterate loop backedges. With 300 unrelated earlier calls, then a full memset and `while (n--) { compose(); stash=buf; }`, followed by popen, the result remains honestly incomplete and truncated but can retain only the generic `memory_chain` leaf, losing the named compose frontier. The short untruncated loop still retains compose. This long-loop loss also occurs on base, round 1 and round 2 and is deferred to a coordinator-filed follow-up.

A forward flow whose `sink.via` is `abi_register` reached a modeled sink argument BN's recovered prototype dropped: the tainted value is in the argument's ABI register. Any flow whose model declares an argument BN dropped carries `sink.arity_mismatch`, **with or without `via`** -- a consumer keying only on `via == "abi_register"` misses the rows whose tainted argument was recovered while another declared argument was dropped. Its fields: `recovered` (the param count BN recovered), `dropped` (every dropped argument the model declares, e.g. the buffer of a bounded write), `register` (the ABI register the tainted arg was read from, null when it was recovered), `callee_ref` (the call target's address; null when it did not resolve), `callee_variadic` (true, false, or null when undetermined), `recovery_advice` (prototype-aware guidance shared by compact text and full detail), and `class_from`, which says what the class rests on. `model`: the tainted argument itself was dropped, so no bound is proven from the register read and the class is the model's own and **unproven** until argument recovery is complete (a bounded copy shows `overflow_len`). `recovered_args`: the class was decided from the recovered arguments only, without using the dropped ones; it need not match the class obtained with a complete prototype (a disclosure that needs a dropped argument, such as `length_shape: residual_chunk` without the buffer, is absent). No class is ever lowered from a register read, so the result can overstate but never hides a flow. The verdict marks such classes (`path_injection[1 via ABI register]`, `bounded_len[1 arity mismatch]`), the flow row says `(arg 1 via x1, arity mismatch)` or `(arg 1, arity mismatch)`, and a following line names the basis and the dropped args; inspect the prototype (`bn proto get <callee_ref>`) and repair only a demonstrated discrepancy with `bn proto set`, then re-run. Repeating a correct variadic declaration does not restore missing arguments. An unmodeled in-binary callee Binary Ninja did not analyse (too large, failed lift) is a caveat `in-binary X was not analysed (...)`, not `external X`, and is listed under `stats.analysis_incomplete_functions`; `bn decompile <addr> --force-analysis` analyses it. An in-binary thunk taint does not follow is `in-binary X is a thunk ...`: it names every tail-call target that resolves (`bn decompile <target>`), else points at `bn disasm`.

Forward taint reads native `MLIL_RET.src` return expressions even when the instruction's `vars_read` is empty. It treats BN's tail-call IL as a return: a modeled, descended, or conservatively tainted callee return reaches the caller's return even though the tail call writes no SSA result. Tainted arguments alone do not taint a callee whose return is clean. This also applies when forcing analysis splits an oversized body into tail-called pieces.

Prototype diagnostics distinguish determined variadic, determined nonvariadic, and unknown types. A correctly variadic callee's `...` arguments may exceed its named formals: an untracked handoff is a modeling frontier (`cause: varargs_not_followed`), not evidence that `...` is missing. Unknown types (`prototype_status_unknown`) require inspection before diagnosis; confirmed extra arguments disagreeing with a nonvariadic declaration (`signature_under_recovered`) support repair. Trace/defuse's nearby stack stores are candidates, not proven call arguments: format literals and contiguous offsets do not establish provenance. Incomplete recovery and tracking still withhold completeness/all-clear claims.

`param:N` selects recovered named formals, not a correctly declared variadic tail. An unavailable formal is not itself evidence that the signature needs repair. Backward aggregate advice for an opaque buffer writer recommends inspecting/modeling its writes and input propagation; a correct prototype alone does not provide a taint model.

Target-requiring commands in taint/trace/defuse hints receive the run's missing target and instance selectors, on both success and refusal paths, including JSON. Existing explicit routing is retained. Lifecycle and other non-target recovery commands keep their own spelling and arguments: in particular, `bn session start` must not acquire an existing-instance `-i`. Concrete function, callee, and variable locators in commands are shell-quoted. Taint and trace caveat prose uses display names by default and raw symbols under `--mangled`; structural symbol keys and runnable command locators remain raw.

Use `--models FILE` for a known wrapper; keys are current symbol names (including `sub_*` on stripped targets), never addresses, and entries nest `sink` or `sources`. For `app_recv(fd, len, buf)`, `{"app_recv":{"sink":{"class":"overflow_len","len_arg":1,"buf_arg":2}}}` models a bounded-write sink; `{"app_recv":{"sources":[{"to":"*arg:2"},{"to":"ret"}]}}` seeds its output buffer and return. `sources` is a list of `to` rules: `*arg:N` means the pointed-to buffer, `arg:N` its value, and `ret` the return. An entry that puts the sink-arming fields (`class`, `tainted_args`, `len_arg`, `buf_arg`) beside the symbol with no `sink` under it, declares no recognized role at all, or declares a role with nothing in it (`"sources": []`, `"propagates": []`, a `varargs` without `to`) is refused with the expected shape named; annotation keys beside a real role are left alone.

Overlay rules are the same for `taint models --models` and `taint forward/backward --models`:

- An **annotation-only** entry (`return_bound`, `arity_capped`, `destinations_unmodeled`, with no flow role) merges only into an existing **flow-bearing** model of the same name, preserving its flow roles. For example, `{"read":{"return_bound":{"max_from_arg":2}}}` keeps the builtin `read` buffer-source, return-source, and sink roles.
- An entry with **any flow role** — `sources`, `sink`, `propagates`, `writes`, `varargs`, or `continuation` — **replaces the entire model entry**, even when it also supplies annotations. Omitted roles are not inherited.
- A benign `{}` builtin such as `puts` is **not annotatable**: an annotation-only entry for it is refused, just as for a name with no existing model. To model flow, supply the flow role explicitly. Supplying `{}` instead replaces the entry with a benign marker.

For example, this mixed flow/annotation overlay replaces `read`; it keeps only the declared return source and return bound, dropping the builtin buffer source (`*arg:1`) and sink:

```json
{"read": {"return_bound": {"max_from_arg": 2}, "sources": [{"to": "ret"}]}}
```

The `models:` header counts only entries that carry a role; an empty `{}` or a `_comment`-only entry (a benign function that neither sources, propagates nor sinks taint) is reported separately as `benign`. `bn taint models` lists a `writes` role (`bzero`) under propagators as `literal->*arg:N`.

## Caller-static mapping

`bn callsites` returns native `call_addr` and post-call `caller_static` (the return address). Prefer it over hand-written `py exec` for exact caller mapping:

```bash
bn callsites parse_record --within process_message --caller-static
bn callsites parse_record --within-file /tmp/callers.txt --format json
```

`--within-file` accepts one function identifier per non-empty line, with `#` comments. Each text label (`call_addr`, `caller_static`, `containing_function:`, `callee:`, `hlil_statement:`, `pre_branch_condition:`, `call_index:`, the `context:` block's `call_instruction`) is the JSON key that carries the value. A null `hlil_statement` means BN could not localize a safe statement; JSON may include a bounded `decompile_excerpt` for context. The excerpt is built for the requested page, so use `--limit` to bound its cost. Caller enumeration can stop at its budget; a short list with `caller_scan_truncated: true` is not proof that other callers do not exist.
