# bn reference — reading

Read-command catalog for the `bn` skill. Open when surveying/decompiling. See `../SKILL.md` for the map.
## Commands

```bash
bn target info
bn target list [--format json]                       # open targets + their selectors; `selector` is what -t takes
bn function list [--count] [--min-address 0x401000 --max-address 0x40ffff]
bn function list [--sort {address|size|name}] [--reverse] [--min-size 64] [--mangled]
bn function list [--named | --unnamed]               # meaningful names vs BN's auto sub_* (import thunks in neither)
bn function search attachment [--count]              # --count here = MATCHES, not the whole-binary total; with no --sort, exact name matches list first (an explicit --sort, even address, is plain order)
bn function search main --exact                      # only the function named exactly `main` (case-insensitive), not every *main* substring
bn function search --regex 'attach|detach|follow'
bn function search <q> [--sort … --reverse --min-size N --mangled]
bn function info <fn> [<fn> …] [--verbose] [--blocks]   # several = one round trip, a miss becomes a failed row; --blocks: basic-block ranges + edges
bn decompile <fn> [<fn> …] [--addresses] [--lines 40:80] [--force-analysis] [--include-annotations] [--explain]
bn il <fn> [--view {hlil|mlil|llil}] [--ssa]          # --level is an accepted alias for --view
bn disasm <fn> [--lines 40:80 | --count 20]
bn disasm <addr> --linear [N]                        # up to N (default 32) units: one physical instruction or one undecodable .byte byte; --length N is an alias
bn xrefs <fn-or-addr> [--limit 20]
bn xrefs --field <Struct.field>
bn callsites <callee> --within <fn>
bn callsites <callee> --within-file <path>
bn evidence function <fn> [--context 2] [--callee NAME|ADDR] [--exclude-callee NAME|ADDR] [--compact] [-v]  # per-call ABI args (LLIL/MLIL/HLIL + raw disasm) + thunk detection
bn evidence xrefs <fn-or-addr> [--limit N]           # inbound refs annotated with section/segment/symbol/disasm
bn evidence table <addr> [--entries N] [--stride N]  # interpret memory as a pointer/vtable table (Thumb-normalized)
bn evidence table <addr> --decode relative-int32 --base <addr> [--entries N]  # signed 32-bit offsets + explicit base
bn evidence table <addr> --record-size N --ptr-fields o1,o2  # mixed-record mode: scalar + pointer fields per record
bn evidence table <addr> --record-size N --field cmd:u32@0 --field name:char[16]@8   # typed scalar/string fields
bn evidence calls <reg-fn> --arg-struct N --field type:u8@2 --field cb:ptr@16  # stack-descriptor fields per callsite
bn evidence message <type-string> [--limit N]        # protobuf/RTTI type-name -> xrefs -> nearby metadata table windows
bn evidence init [--limit N]                         # .init_array/.ctors constructor-pointer summary
bn evidence orient                                   # one-shot triage digest under a single read lock: target + analysis state, imports, strings sample, sections
bn evidence surface [--hide-vtables]                 # hidden code surface: init/ctor + vtable/dispatch tables + data- or code-referenced code BN missed
bn evidence virtual-call --at <addr> [--providers <selector>]   # resolve an imported abstract/interface virtual call to the provider's vtable method
bn trace <fn> <addr> [--arg N] [--interprocedural]   # backward SSA slice: trace where a call argument originates
bn dataflow defuse <fn> --var <name|local_id|name#version> [--mangled]   # SSA def site + use sites of one variable
                                                    # a use that is argument set-up for a call whose
                                                    # recovered model dropped its stack-passed args is
                                                    # reported as a `hint: call ... call-model truncation`
bn dataflow callgraph <fn> [--direction {callees|callers|both}] [--per-site] [--mangled]   # resolved edges; text: one row per distinct callee/caller with its count and first sites (--per-site: one per call); indirect targets via value-set, one row per site; callers include indirect calls whose value-set names the function (`kind: indirect`, rendered `(indirect call, value-set)`; off with --no-resolve-indirect); a constant call to a symbol with no function body (`__builtin_memset`) is `direct` with `target.has_body: false`; one row per (site, target); JSON is per site with `display_name`
bn dataflow values <fn> --at 0x401234[:IL_INDEX] [--mangled]   # value-set (possible values) at an instruction; several MLIL SSA instructions computing a value at one address are refused (`ambiguous_instruction`, candidates listed) -- pick one with `--at ADDR:IL_INDEX` (the [N] structured-il prints); the rest at that address are `other_instructions`
bn taint models [--role {source|sink|propagator}] [--class overflow_len] [--present] [--callsites [--all-sites]] [--callsite-limit N] [--mangled]   # known sources/sinks; --present needs a target; --callsites lists real calls by application callers (stub/inline rows counted, shown with --all-sites), named by demangled caller unless --mangled; text prints 10 rows per model and counts the rest (--callsite-limit 0 = all)
bn taint forward -f <fn> --source param:0 [--sink-class recv_overflow]   # untrusted data source→sink across calls (methodology → the `bn-vr` skill); with several --source flags each source is also run alone, and a flow names a source only when exactly that one reaches its sink alone (`source_candidates` lists every source that does; otherwise `multiple`); advice that bn cannot complete is printed as a `template` with UPPER-CASE blanks; a buffer-filling call:/arg: seed gates only unresolved indirect calls in the source function (`indirect_call_unchecked`, syscalls excluded), and its all-clear carries `diagnostics.all_clear_caveats` (see "Receive-buffer coverage" below)
bn taint backward -f <fn> --sink arg:memcpy:2         # slice a sink's args back to their origin; `sink_status[]` gives each call site's status
bn function cfg <fn> [--view {asm|mlil|hlil}]        # basic-block graph: blocks, their instructions, and the typed edges between them
bn function structured-il <fn> [--mangled]          # flat per-instruction list: op plus vars_read/vars_written, no block partitioning
bn proto get <fn>
bn local list <fn>
bn local list --frame <fn>                           # stack frame map: one row per distinct stack offset, saved-register/canary markers, bytes to the canary
bn data vars --at <addr|name>                        # the typed data variable at an address, symbol name or rendered data_<hex>
bn data vars --start <addr|name> --end <addr|name>   # typed data variables in an address window [start, end)
bn data symbols [--query <q>] [--limit N] [--offset N]   # named DataSymbols, internal ones included (paged: 100 by default); --query = case-insensitive substring
bn read <addr|name> [N] [--encoding {hex|escaped|bytes}]   # a symbol name or data_<hex> resolves like xrefs (`note: resolved … @ 0x…`)
bn types [--query <q>]
bn types show <name>
bn struct show <name>                                 # a struct BN records bases for (e.g. from debug info) shows `: Base` and inherited fields tagged `[from Base]` (JSON: `bases`, `inherited_members`); `types declare` records none yet (#965)
bn class list [--include-hidden] [--no-stl] [--no-vendor [NS,...]] [--local] [--query <substr>]   # C++ classes from demangled symbols + RTTI (+ your own declared class types under --include-hidden)
bn class show <Name>                                  # one class: methods, vtable, size, bases, instances; falls back to a class type you declared
bn strings [--query <q>] [--regex] [--min-length 5] [--section .rodata] [--no-crt] [--with-xrefs] [--include-noise]
bn imports [--summary] [--with-callers]               # rows carry `library` (+ `library_source`); DT_NEEDED is in `target info`
bn exports [--count]                                 # global/weak definitions from any symbol table, not loader-visible exports
bn go functions [--summary | --count]                # recover Go names from .gopclntab (then `bn go rename`, a mutation)
bn sections [--query <q>]
bn tag list [--type Bookmarks --query <substr>]      # tags at all scopes; `--type Bookmarks` is the bookmarks tag
                                                     # UNFILTERED it walks EVERY function (function tags + address tags);
                                                     # narrow with --function <fn>, or --data for data tags alone
bn tag get 0x401000                                # tags at one address
bn tag get --function <fn>                          # whole-function tags
bn tag types                                         # tag types (built-in + custom)
bn comment list [--query <q>] [--scope {all|address|function}]   # `all` (default) includes function docs
bn comment get --address 0x...                     # address comment
bn comment get --function <fn>                     # function documentation comment
bn bundle function <fn> [--out bundle.json]          # export; does not mutate the BNDB
```

`dataflow values` keeps the instruction/assignment-source set in `possible_values`,
with `value_basis` identifying which expression supplied it. For a call or tail
call, `call_destination` separately reports the destination `expression`,
`value_basis: "destination_expression"` and its own `possible_values`. Destination
addresses are not possible return values. Unknown destinations remain unknown;
the destination set does not replace a determined instruction value or change
assignment-source selection.


Notes:

- `function search` is a case-insensitive substring search over the demangled display name. Use `--exact` for a known API, `--word` for an identifier token, or an anchored `--regex` for a family. A regex-shaped zero-hit literal query may be retried as a regex; `regex_fallback` discloses that choice. Confirm a source or sink against the import and actual call target, not its name alone.
- **Names in text are demangled.** `function list/search/info`, `xrefs`, `callsites`, `comment list`, `exports`, `strings --with-xrefs`, `taint forward/backward` (header, flow and slice sinks, slice origins, signatures, frontier callees) and `trace` (header, call boundaries, out-param fills, crossed functions, frontier roll-up) print the demangled display name (`demo::Widget::handle`), the spelling `decompile` and `class show` use, and any of them resolves as an identifier; where overloads share one display name in a `strings --with-xrefs` list, each carries its address. JSON keeps the raw `name` (mangled for C++) beside `display_name` (`function_display_name` on `comment list`, `xrefs --field` rows and `trace`; `callee_display_name` on a taint `sink`, a `trace` step and `trace`'s `arg_label`; `origin_callee_display_name` on a backward slice; `out_param_callee_display_name` on a `trace` out-param step; `signature.rendered_display` beside the raw grouping key `signature.rendered`). The `callee` of a taint reached sink, frontier leaf, backward origin, backward `slices[].sink` and `sink_status[]` row is always the symbol the binary calls (through a thunk, the symbol the thunk calls) (`__strcpy_chk`, `__isoc99_fscanf`, `_ZNSt13basic_filebuf…`; `sink.callee_symbol` is the same raw symbol); the model it was judged by, whose key drops leading underscores and folds aliases (`strcpy_chk`, `fscanf`), is the separate `model` key, present only when it differs from `callee` (a sink's `src_fill.callee` follows the same rule). `signature.rendered_symbol` spells the signature with real symbols, and a C sink's display name is its real symbol. `--mangled` prints raw names instead (real symbols for a taint sink and its signature); on `function search` it also matches raw names, and a default search whose query only a mangled name contains reports `mangled_only_matches`. Free-text caveats and notes keep raw names. The old `--demangle` is still accepted and changes nothing.
- `function list --count` counts all functions; `function search <query> --count` counts matches. `--sort size --reverse --min-size N` is useful for large functions. `--sort name` orders by the name the text shows: the demangled display name, or the raw name under `--mangled`. `--named` / `--unnamed` separate meaningful names from auto `sub_*` names.
- `exports` lists global/weak function and data definitions from any symbol table in BN's combined symbols; `exports list` is an alias, and `--count` counts that same population. It does **not** establish dynamic-loader visibility. On ELF, a global definition may exist only in `.symtab`, not `.dynsym`; use `readelf --dyn-syms` or `nm -D --defined-only` to inspect the dynamic table instead. The synthetic ELF case reported in [#921](https://github.com/m4ul3r/bn/issues/921) had 235 definitions under `bn exports --count` but only 2 under `nm -D --defined-only`: those are different populations, not evidence that all 235 are dynamically exported.
- **Duplicate function start addresses are disclosed (#757).** Binary Ninja can hold more than one Function record for one start address. Where an answer holds such an address it publishes `duplicate_starts_collapsed` / `duplicate_starts_unresolved`, and every text face that answer reaches discloses it too. This entry states no more than that on purpose: every summary of what the collapse does to a given answer has been false on some shape of it, so the answer carries that truth and this page does not restate it.
- `evidence orient` text prints every returned string row and section name; `--strings-limit` bounds the sample, and the header names how many candidate strings the min-length / data-section filter dropped (`filtered`).
- When the `evidence orient` strings sample is truncated, its text prints a runnable `bn evidence orient --strings-limit N` command to request the full sampled population; append the same `-i` / `-t` routing options if needed.
- `evidence function` uses display names in its header and target lines by default, and raw names for both with `--mangled`; JSON retains both names. This is deliberately not a universal name-rewriting flag: decompile warning prose, `class show` thunk target labels, and `evidence table` / `evidence init` pointer targets retain raw symbol names (#1006). Raw labels distinguish ABI entries such as D1/D0 destructors whose display names collide.
- `evidence function --callee NAME|ADDR` keeps only calls to that callee and `--exclude-callee NAME|ADDR` drops them; both repeat (`--callee` is a union, and exclusion applies after it). A selector matches a call when it equals the resolved callee function's raw name or display name exactly, or parses as an address (hex `0x..` or decimal) equal to that function's entry or the call's normalized target. So `--exclude-callee 'operator delete'` drops calls to both `_ZdlPv` and `_ZdlPvm`, because both display as `operator delete`; `--exclude-callee _ZdlPv` drops only that overload. A call without a resolved callee function (an indirect call, or a target BN has no function at) is never matched by `--callee` and is always kept by `--exclude-callee`. The filter runs before `--address-window` and `--offset`/`--limit`: `total_calls` stays the full count, `matched_calls` and `has_more` page over what the filters kept, and JSON adds `callee_filter: {callee, exclude_callee, excluded}` (`excluded` = calls the callee filter removed). Text says `calls: N of M matching the callee filter (of T total; X excluded)`, or `calls: 0 -- no call matched the callee filter (...)`. Hoisted warnings and `arity_witness_counts` still cover every call, and filtering alone does not defer the Pseudo-C decompile.
- `evidence function` text prints a row's `witnesses:` line only when one of its verdicts is a `contradiction`; the arity tally (or a line of its own) then says `per-row witness lines shown only for contradictions (N hidden; --verbose shows all)`. `--verbose`/`-v` prints every row's line. `--compact` prints one line per call, `- <addr>  <direct|indirect>[ <operation>]  <target or ?>  (<arguments, each with what it resolves to>)`, leaving out only the IL lines, the instruction context and the diagnostics' advice prose; the operation is shown when it is not a plain `LLIL_CALL` (a tail call, say). Tags: `[args: <source> <confidence>]` (how far the list can be trusted, as on the full row), then, only where they apply and with the facts the full row states, `[arity: unknown, no recovered prototype[, saturates the ABI argument registers]]`, `[arity: mismatch, prototype declares N]`, `[arity: unverified, prototype declares N but <library> declares M]`, `[target unresolved, no signature to check against]`, `[variadic: under-recovered, count: heuristic]` or `[variadic: <callee> format='…' conversions=N, count: heuristic]` (the format count is a heuristic, separate from the recovered argument list), `[witness: contradiction]`; the witness-line rule and `--verbose` apply under each compact row as well; the card above the call list is unchanged. JSON is unaffected by either switch.
- `evidence orient` reports `existing_annotations` at the top level. A restored `.bndb` can carry earlier names and comments. `decompile` omits stored annotation bodies by default; `--include-annotations` opts in. Redaction covers matching standalone or inline `//` annotation lines, not arbitrary block comments or differently rendered text. Use `--addresses` when mapping a rendered line back to code.
  - A comment this bridge wrote and verified (`bn comment set`, `--function`, or `batch apply`) is not redacted: it renders as `// [this session] <body>`. Its location and body must both match; a body also stored somewhere else stays redacted. `py exec` writes do not count. Text mode ends with `note: N stored comment line(s) hidden as <annotation redacted>`, and JSON `annotation_summary` carries `hidden` and `session_shown`.
  - `comment list` and `comment get` rows carry the same judgment as `written_this_session` (`comment get --function` also has `function_doc_written_this_session`), and text marks those rows `[this session]` (the single-comment `comment get <addr>` text stays the bare body). `false` means unknown, not "someone else wrote it": a `py exec` write, a GUI edit, a comment written before a `session restart`, or one from a database all read `false`.
- `strings` ranks a dump by the section a string sits in: `.rodata`-like (ReadOnlyData) first, `.data`-like next, then code bytes that decode as text and linker metadata, in address order within each tier; where sections overlap the narrowest claiming one decides. An address no section claims is noise only when the view has a ReadOnlyCode section and the address is in an executable segment; on a raw image or a section-header-stripped ELF (BN adds only `.synthetic_builtins`) nothing is ranked and the dump is plain address order. `noise_strings` / `noise_sections` name the last tier and `data_sections` the data sections the listing drew on; the text tip names them only when noise is non-empty, recommends `--section <top data section>` only on an unfiltered dump, and `--section` pins one section in address order. `evidence orient` samples only the first two tiers (`sample_sections` says which, in sampled order) and names the fallback in `sample_fallback` when a view has no strings there.
- `bn decompile handle parse_file main` uses one bridge call and preserves the requested order. A missing identifier keeps its row and makes the command exit 2. One identifier retains the single-function `.text` shape; several return `{"kind": "decompile_batch", "requested": 3, "resolved": 2, "functions": [...]}`. Each `functions[]` row is `{"identifier", "ok": true, "decompiled": {"function": {"name", "address"}, "text", "warnings", "warning_rows", ...}}` -- the single-function result under `decompiled` -- or `{"identifier", "ok": false, "error"}`. The name and address are at `.functions[].decompiled.function.name` / `.address` (the row itself has neither; `.identifier` is what you asked for), and the body at `.functions[].decompiled.text`, not `.items[]`. An `analysis_skipped` stub is not a body; `--force-analysis` analyzes that function and can be slow.
- `function info` reports the two counts `xrefs` reports for the function, by its definitions: `code_ref_count` (code references, plus callers of a same-name PLT stub) and `data_ref_count` (data references, such as a stored function pointer). Text: `xrefs: N code, M data`. A function reached only through a stored pointer can read `code_ref_count: 0` beside a non-zero `data_ref_count`.
- `function info` and `proto get` carry BN's provenance for the prototype. `has_user_type` is BN's per-function flag as BN reports it; it is not an origin. BN sets it for an analyst's `proto set`, for its DWARF/PDB import (which applies debug-info prototypes as user types) and, after a save and reopen, for nearly every function of the database, inferred prototypes included. `type_source` therefore states only what can be proven: `user` when this bridge set and verified the prototype in this process (`proto set`, or a batch `set_prototype`; the record is gone after a bridge restart or a reopen of the database), `auto` when the flag is clear (analysis inference, or a prototype applied from a platform type library), and `unknown` when the flag is set without that proof; null when BN reports no flag. One flag covers the return type too. `prototype_confidence` is the lowest of BN's 0–255 confidences for the return type, the parameter list, each parameter's type and the calling convention; `return_type_confidence` is the return type's own. 255 is BN's maximum, and a lower value is an inference to cross-check against `disasm`, for example a return width BN guessed. Text: `type: auto, confidence 96 (return type 128)`, with ` (has_user_type set)` after the source when the flag is set.
- `size` is the summed bytes of the function's basic blocks, not an address range. `span_start`..`span_end` (exclusive) bounds every block, and `contiguous: false` means bytes the function does not own lie between its blocks, such as a Thumb literal pool or another function. Then `span_end - span_start` exceeds `size`. Text: `size: 42  span 0x8000..0x8030 (discontiguous)`.
- An address inside a function is reported in `resolved_from` (`requested_address`, `offset` from the function start). In a Thumb function, an odd address carries the interworking bit, not an instruction byte. `resolved_from.normalized` is then the address with bit 0 cleared, and `offset` is measured from it: an odd entry pointer reads `offset: "+0x0"` with `normalized` equal to the function's address.
- `proto get` prints the display name on its text prototype line; `--mangled` selects the raw symbol name. Display names are descriptive, not necessarily valid C declarators. JSON `function` carries `name`, `raw_name` and `display_name`. `implicit_object_note` is neutral current-state reporting: the first parameter's current name and type (or the absence of parameters), beside the available observation that BN's demangled signature describes a leading object parameter. It does not say who supplied the name/type, attribute recovery, infer parameter correspondence or verify an ABI. The note does not use the function-level user-type flag (reported on its own as `has_user_type`) or per-variable user-definition flags to infer who supplied a parameter. For `proto set`, BN's parser rejects a parameter named `this`; the refusal recommends `self` or a free numbered variant if that name is already used. Apply the exact suggested spelling. Named function types such as `ns::Callback` retain named-type resolution. Nested backticked template types are passed to BN's parser; a parser or fallback refusal is a clean `invalid_request`, not an internal exception.
- `proto get` on a function with parameters adds `first_argument_entry_value` (`{direct_call_sites, checked, entry_value, registers, truncated}`) and a text note: at how many direct call sites (a constant call or tail-call target, MLIL SSA; indirect calls are not counted) the first argument is the caller's own entry value of a register (SSA version 0, rendered `entry_rdi`/`entry_x0`), i.e. a value that caller never set. Itanium mangling does not mark a member static, so BN gives every `Class::method` a leading `this`; callers passing their own entry value is evidence to weigh, not a static verdict, and a member forwarding its own incoming `this` also counts. At most 32 call sites are inspected (`truncated`).
- `proto get` lists named types its current prototype references that the view does not define (`undefined_types[]`, `undefined_type_note`). `proto set` refuses such a prototype (`Reference to unknown type`) until the type is declared; for a `struct`/`class` reference the note prints the command, e.g. ``bn types declare 'struct `ns::Cls`;'``. The prototype `proto get` prints is not itself a valid `proto set` string: spell `::` names in backticks and rename a `this` parameter (``void* method(struct `ns::Cls`* self, void* arg2)``).
- `decompile` can disclose a **struct layout candidate** in `.warnings` (text mode prints its one-line summary; `--explain` prints the full note) for an incoming `void *` parameter. The witness is direct MLIL-SSA loads/stores at two or more distinct constant byte offsets, all matching complete flat scalar members' offsets and widths in exactly one compared struct layout. Every other use of the incoming pointer value except a comparison (a copy into another variable, a PHI, a derived pointer, a call argument, a stored value, or a taken address) disqualifies the parameter, because accesses through that value would escape the witness. The note names the parameter, layout, fields, and access widths, and states that layouts holding the offsets in nested, union, array, or base-class members were not compared; it is evidence of layout compatibility, **not recovered type identity**. Review with `struct show` and `disasm`, then use `proto get` and explicitly apply the full edited prototype with `proto set`, preserving the other parameters, qualifiers, and calling convention. For example, if the current prototype is `uint64_t handle(void *c)` and the candidate is confirmed, use `bn proto set handle 'uint64_t handle(struct cfg *c)'`.
  - This assistance never applies a type or changes the rendered body on read; already-typed pointers keep their existing rendering. Batch decompilation carries the same per-function warnings.
  - Known layouts include loader-provided and other auto-defined structs already in the view, not only user declarations. A missing analyst-defined type does not mean no compatible layout exists; adding it can make an existing match ambiguous.
  - Named scalar member types are resolved through up to 16 typedef references before matching, only for members at an observed offset and width, with exactly one view type lookup per hop (by ID, or by qualified name when no ID is present). The shared resolver used by `struct show` and class declaration reads enforces the same lookup budget and detects cycles by reference identity, not Python wrapper identity. An unresolved ID is not retried by name. Unresolved, cyclic, or longer chains and non-scalar terminal types do not supply a member witness. Distinct concrete structs remain distinct candidates even when their members differ only in typedef spelling; aliases of a whole struct do not add candidates.
  - Matching distinguishes a positive scalar witness, an excluded layout, and an unclassifiable member. An unresolved, cyclic, or over-budget member at a matching offset and width, or an access overlapping a bitfield's storage unit, overlapping members, or the span from a zero-width member (an unresolved named type or flexible array) to the end of its layout, cannot supply a hint, but an otherwise compatible flat layout containing it blocks any claim of a unique candidate. A trailing flexible array covers no bytes. A base-less `class` layout, and a layout whose members overrun its recorded width (for example after redeclaring an embedded type), are compared like a struct and block uniqueness when compatible, but are never themselves suggested. A layout whose flat scalar members do not match an observed offset/width, or whose observed member is non-scalar, is excluded from the comparison; that is a scope limit, not proof that it cannot be the parameter's type. Opaque types elsewhere in the view, including unobserved members and bitfields away from every access, do not by themselves suppress hints.
  - Scope is deliberately narrow: no pointer-alias/dataflow recovery, computed indexes, reassigned pointer values, class suggestions, or comparison of accesses that land inside a nested struct, union, array, or base-class member. Such layouts can be compatible yet neither block nor appear, which the warning discloses. Conflicting widths/offsets or multiple matching layouts produce no suggestion. A missing hint is **not** proof that no struct could fit, and a hint is **not** proof that no other type fits.
- `decompile` JSON keeps `warnings` as a list of sentences, the same shape `il`, `bundle` and `evidence` use, and adds `warning_rows`: the same warnings in the same order as `{code, summary, detail, address}` plus structured facts (`calls`, `addresses`, `types`, ...). `address` is the first reported site for a grouped warning, or the function entry for a function-wide warning; grouped site lists remain complete. Each `detail` is the matching `warnings` sentence. Text prints one `warning[<code>]: <summary>` line each; `--explain` adds the detail (what it means, what to do) under each. Filter on the code, not on `^warning`: dropping every warning also drops the dropped-argument findings. Codes: `arity`, `jump`, `branch`, `offset`, `select`, `layout`, `split`, `callee_split`, `fragment`, `string`, `stub`, `thunk`, `forced_data`. A `/* bn: ... */` comment on a Pseudo-C line (after the code, before any `//` comment) is bn's note, not Binary Ninja's; a `❓` line is control flow Binary Ninja could not resolve.
- Beyond struct layout candidates, `decompile` warns about these ways the Pseudo-C can mislead:
  - **call arity** (`arity`): a call rendered with fewer arguments than the call site passes. This happens when BN's prototype for a library callee is too short; type libraries often leave out `this` and trailing parameters (`std::filebuf::open(&f)` for `open(&f, path, mode)`). The warning is backed by the demangled signature of a mangled callee, or, for an import, by the argument registers written since the previous call and read by nothing else (a `csel` that computes an argument right before the call counts; registers only its comparison reads do not). It also covers a mangled callee rendered with *more* arguments than its signature takes. The call line itself carries `/* bn: +2 args not rendered: x1 = [sp].q, x2 = 0x30 */`, naming each dropped register and, when it is known, its value: a constant, a parameter name (cast when only its low bits were copied: `(uint32_t)arg2`), or the register-level source. A register overwritten before the call -- by any write, including a split pair or an intrinsic such as `mrs` -- is never shown as a value by that walk; BN's own dataflow value at the call fills it in when it is a constant (`adrp x1, ...; add x1, x1, #0x8e0` reads `x1 = 0x4008e0 (on_packet)`), and an address the view names carries that name. A bare register name means unknown. A note goes on the line of the statement holding the call (`int32_t fd = socket(...)`, `if (strcmp(...))`) and names its callee when that line is not the call alone. JSON `calls[]` has one row per call, with `shape` (`shortfall`, `excess` or `no_parameters`). Sized `operator delete(void*, size_t)` is not reported: BN always drops its size, which is allocator bookkeeping. Read the real arguments with the `bn callsites <callee address> --within <fn address> --context 4` the warning prints filled in; `callsites` rows carry the same finding as `arity` (`arity: +1 arg not rendered: x1 = ...`).
    - A callee whose prototype declares **no parameters** -- an import BN's type library has no entry for is `int64_t socket()` -- is rendered with whatever argument registers BN's call-site analysis picked (`socket(1, 2, 0, __stack_chk_guard, 0)`). Those calls are `shape: "no_parameters"`: the line reads `/* bn: socket: prototype declares no params; the 5 args shown are BN's guess */`, `expected` is null, and the warning names the registers the call site does write. It claims no argument count; apply the real prototype with `proto set`. A call with its own call-type adjustment, or a callee BN determined variadic, is not reported this way.
  - **unresolved jump** (`jump`): an indirect jump with no target BN resolved and no successor block, rendered `❓ /* jump -> <expr> */`. The `❓` marks control flow Binary Ninja could not resolve. There is one row per machine jump, even when BN repeats it in several switch cases, and every line that shows a copy carries `/* bn: unresolved jump: a tail call (args not rendered) or a computed goto */`. The row names the target expression and both readings, and claims neither: a tail call through a pointer, leaving the function, whose arguments are in the argument registers at the jump and are not rendered (read them in `disasm`; type the callee with `proto set`, or the object the pointer is loaded from, so BN renders the call), or a computed goto or jump table BN did not follow, staying in the function, whose code may not be part of the function's decompile or disassembly. No step is sure to find those targets. When the target expression reads a data address (`table` in the row), `xrefs <table>` lists the code that reads and writes it -- references to the base address only, so a store to a later entry may be missing; for a table filled at run time (a `.bss` table) the writes are where the target addresses are stored -- and `evidence table <table>` reads its current bytes as absolute pointers, while `evidence table <table> --decode relative-int32 --base <table>` reads them as signed 4-byte offsets added to the table's address (a table whose offsets count from another base needs that base); either names targets only for a static table, and a run-time table reads as zeros. Stores in the decompile that write code or table addresses into what the jump reads may name them too; a table a store names is read with `evidence table <address>`, or with `--decode relative-int32 --base <address>` when its entries are 4-byte offsets. For a `data_<hex>` placeholder, use its hexadecimal address; resolve a symbol with `xrefs <symbol>` and read the address in its header. Read a target address's code with `disasm <target> --linear 16`. With `--explain` the detail is wrapped into short lines, each backticked command kept whole. Import stubs and the PLT header are skipped. Telling the two readings apart is not attempted.
  - **resolved indirect branch** (`branch`): reports only targets in BN's own indirect-branch records, including any target addresses BN models as separate function starts. `targets[].function` names those separate bodies; read them with `decompile <address>`. This does not recover missing table entries, establish that all destinations are known, or classify a branch as a computed goto or tail call.
  - **`__offset(T, N)`** (`offset`): BN's spelling for a pointer N bytes into an object of type T. The warning looks T up the way `types show` does (by the rendered qualified name, so `std::_Rb_tree_node_base` and template names are found): it names the ones defined in the view, and calls the others what they usually are, named references BN made from a symbol or demangled signature with no layout (so `types show` will not find them; create one with `types declare`). A `vtable_for_C` base is C's vtable object; `+2 * pointer size` is its address point, a vptr value. The entire summary is capped at 240 characters, listing whole names only and counts for omitted names. JSON and `--explain` keep all names.
  - **split body**: a block that runs straight into another function's entry without a branch, or a prototype whose parameters sit in callee-saved/link registers (`arg3 @ x19`, `arg5 @ fp`). Both usually mean BN split the body at a shared tail. Callers of such a function get a `callee ... takes parameters in callee-saved/link registers` warning, `proto get` prints the same notes, and `disasm` prints `// falls through into <fn>` right after the instruction that runs into it. The `proto set` advice is given only for a function something calls, directly or through a data reference (a vtable slot or function-pointer table); a piece entered only by jumps or fall-through is told its registers are live-ins, not arguments. Removing an erroneous tail entry allows reanalysis but does not guarantee merged or extended function bounds.
    - For a fall-through split, the warning's repair command uses the actual suspected tail entry address: `bn function delete <address>`. Inspect both bodies before applying. Deletion has **no clean undo**, and `--preview` refuses without changes; a `function_delete` batch must contain only that one operation. Its result reports whether the entry disappeared, whether reanalysis completed, and `{address, name}` rows for bodies containing the deleted entry. Containment is not proof of a full-tail merge: re-read the bodies afterward.
  - **EH/cold fragment**: an unnamed exception-cleanup (landing pad) or cold-path piece BN made a function of its own gets one note instead: its callee-saved-register parameters are its parent's live registers, not a split to repair. A fragment has an `_Unwind_Exception` parameter or a `.cold` name, is never called nor address-taken and either never returns or has no references at all, or never returns and is called only by other fragments.
  - **raw string pointer** (`string`): a call argument rendered as a bare address (`0x400b90`) that holds a NUL-terminated string BN never defined, so `strings` does not list it either. It needs at least three printable bytes, or a callee that takes a narrow `char *` there: by its prototype, its demangled signature, or, for an import or a prototype that stops short, its C library name (a built-in list checked against glibc plus the format argument of the printf/scanf family, else the platform type library's prototype: `strcmp(arg, 0x661bd8)` names `"C"` even when `strcmp` is untyped). BN's placeholder `&data_400b90` counts only with that `char *` evidence, since BN gave the address a data variable that may be an `int[]` or a struct (`setlocale(6, &data_400b90)` is named; `memcmp(p, &data_…, 16)` is not). A prototype applied with `proto set` is never overridden by the name lookup. Shorter runs passed elsewhere are too often an `int[]`, UTF-16 text or a struct. Opt in to defining it with the `bn data retype <addr> 'char[N]'` command the warning prints.
- `disasm --lines START:END` and `--count N` count rendered function rows, not bytes. `disasm <addr> --linear N` walks physical instructions and undecodable `.byte` units outside recovered blocks. For width, branch, or bounds claims, inspect the instruction operands. On Thumb, include the preceding `IT` instruction and every covered instruction. A call or branch whose destination (from BN's instruction info) the view names prints that name after it, `bl 0x400880 <socket>`, `b 0x400b60 <fold_value>`, here and in `callsites` context; a local branch target, an `adrp` page and any other immediate stay bare.
- `class list` groups demangled C++ methods and RTTI. Its default favors RTTI/constructor-supported classes and hides RTTI artifacts -- construction vtables and typeinfo for non-class types (`bool`, `char*`, a function type) -- with a count in the header; `--include-hidden` (older spelling `--all`) adds those, name-only clusters and user-declared class/struct/union types. It does not change paging: use `--limit`/`--offset`. `--no-stl` hides std/ABI classes; `--no-vendor` hides `boost::` plus any comma-separated top-level namespaces you name (`--no-vendor Poco,acme`); `--local` hides classes with nothing defined in this binary (every RTTI object an import or a copy relocation of one, every clustered method an import stub), which text rows otherwise mark `[defined in another module]`; its count covers only rows the listing would otherwise show. A name-only cluster may be a namespace; a declared-only card does not prove methods or vtables are absent. One class demangled under two spellings (`Holder<std::string>` and its `basic_string` expansion) is one card, reachable by either through `class show` and `--query` alike; the other spellings are `aliases`. `class show` reports ambiguity and scan caps rather than choosing a same-leaf class or treating a truncated vtable as complete. A vtable ends at the next object (an RTTI record or vtable BN names at that address, or a typeinfo's vptr), never inside it; BN's own `VTable` width is reported as `bn_vtable_slots` but never bounds the walk, because BN stops that struct at the first null word and an abstract class's zeroed destructor entries sit mid-table. An imported class's typeinfo is an import slot: `bases` is empty with a note, not decoded from GOT words. A `secondary vtable` recovered by typeinfo backwalk is `[rtti]` when its slots are this class's `_ZThn<N>_` thunks at that offset-to-top or BN's own `vtable for X{for `Y'}` symbol names it, else `[heuristic]`; a candidate whose word[0] is a mapped pointer or out of bound is listed under `rejected_secondary_candidates` with the observed reason. Confirm a `[heuristic]` secondary with `evidence table` before reporting an inheritance edge.
- A library (std/ABI) base that two or more `__si_class_type_info` records in the binary name as their only base carries the count: `: std::X (only base of N classes here)` on the list row (`base_sole_base_of` in JSON, `sole_base_of` on the card's base) and a `note:` on the card that prints the `evidence table` command for the class's typeinfo record. It is a count of what the bytes say, not a verdict: a std functor-trait template as the only base of many unrelated classes is worth checking against the record.
- Typeinfo records BN put no symbol on are LISTED, never named (#1035.5, #1049): in a stripped non-PIE C++ build the ABI's `__cxxabiv1::__{,si_,vmi_}class_type_info` vtables are COPY-relocated into the executable and BN's RTTI analysis names no typeinfo, so the lens has no class rows there. `class list` (and `--count`) then carries `typeinfo_scan_candidates` and `typeinfo_scan_listing`: each aligned data word equal to one of those vtables' address points where BN named nothing, as `{address, layout, name_string, reason}` (the first 64; the count is whole), with a `!` line in text. Nothing establishes that a candidate is a typeinfo object or that its raw name string names a class (a function's `.extern` endpoint, or imported data named like a class typeinfo, can sit in the base word), so no class row, card or `class apply-types` input comes from them; read one with `bn evidence table <address>`. The scan reads at most 64 MiB of data sections per view (`abi_scan_truncated`, and a `!` line, when it stops) and is memoised on the view's DATA, so a rename does not re-read it.
- For returned-page RTTI-backed records without a vtable symbol, `class list` tries the same primary typeinfo backwalk as `class show`, even after methods are named, sharing one monotonic budget across the page: 50 ms by default, `--vtable-budget SECONDS` for up to 30 s. Recovered rows carry `vtable_status: "recovered"` and `vtable_slot_count` (`slots=N` in text); `method_count` still counts clustered methods, not table entries. A capped table has an unknown slot count. Budget exhaustion is explicit in text and `vtable_recovery_budget_exhausted` (the budget used is `vtable_recovery_budget_seconds`); unchecked rows have `has_vtable: null`, not a false `no-vtable`. Missing/raising optional APIs, failed or short raw reads, unreadable slot rows, and imported RTTI leave that row unknown with `vtable_status: "unavailable"` and a null slot count, without aborting the page. Imported RTTI does not establish an empty table in another module. `--count` skips recovery.
- `class show` reads the body of each UNNAMED primary-vtable slot (up to 256 MLIL instructions) and prints neutral facts beside it: the vtable address points it writes (named by the RTTI they point at, and `into parameter 0` when the constant store lands at offset 0 of BN's parameter-0 variable), up to four functions it calls, and whether it calls the global `operator delete`. No role and no parameter type is inferred from them: a destructor writes an address point and a deleting destructor calls `operator delete`, but so do a virtual `reset` that placement-constructs into an argument, a `clone`, and `release() { delete this; }`; and the store fact does not tell a full vptr store from a partial-width one or a folded reload. Read the slot's prototype with `bn proto get <address>` and its decompile before naming or typing it.
- A decoded vtable's `address` is the Itanium object head; slot zero is at `address + 2 * pointer_size`. In stripped binaries BN may synthesize `vtable for X` on slot zero instead. The class lens normalizes that address only after reading a preceding zero offset-to-top, local typeinfo for the same class, and fully resolved nonvirtual RTTI ancestry; it does not move BN's symbol. ABI selector provenance first checks the object head two words before the typeinfo vptr, so an adjacent unrelated extern at the exact vptr cannot override it. Virtual-base ancestry (including inherited virtual bases), imported/unresolved bases, unreadable base records, or an unknown ABI RTTI selector leave the original address and conservative `no_local_vtable_body`: construction tables share the same header, even when there is only one candidate. An existing object head is kept, import/GOT aliases are not normalized, and a nonzero-offset candidate remains the secondary backwalk's responsibility, never promoted to a primary. Stored-global instance lookup uses this proven slot-zero address point for decoded layouts, including capped or unreadable slot scans. An undecoded entry or `no_local_vtable_body` does not authorize adding two pointers: lookup keeps the original symbol address. Named VTT and construction-table objects are excluded only within BN's proven data-object width; without a width, only their first word has proven ownership. Consecutive address-point pointers and the next symbol do not prove an untyped VTT's extent: an unnamed neighboring object can have the same vptr. Remaining references are preserved with a note that they may include untyped ABI entries; stored-global totals count references, not proven instances. Unnamed ABI containers are not identified.
- `class show`'s vtable (and each secondary) also carries `address_point`, slot zero: the vptr value objects store, so `xrefs` on it finds the constructors that stamp it, while `xrefs` on `address` usually finds nothing. Text prints `vtable @ <address>, address point <address_point>`.
- A `class show` name that several classes share as a leaf (`Handler` for `svc::Handler` and `net::Handler`, RTTI or declared) is refused with exit 2 and `status: "ambiguous_class"`, the same refusal shape as every other exit-2 read. Under `--format json`, stdout is `{"ok": false, "status": "ambiguous_class", "error", "requested": {"name"}, "observed": {"matches": [<card>, ...]}}`. The message names each class and a `bn class show -- <full name>` to re-run.
- `callsites` reports data locations holding the callee's address separately from recovered calls. For locations inside a defined ELF `_ZTV` object's symbol extent, its note prints `bn class show -- <class>` only when that full canonical name uniquely selects the same object in the current class registry. JSON adds `callee_data_ref_vtables` with `evidence: "elf_symbol_size"`; extents are mapped using BN's image-base metadata, not nearest-symbol guesses. Anonymous/stripped tables, ambiguous or noncanonical names, mismatched symbols, and unsupported/budgeted proof surfaces fall back to `bn xrefs <data-location>`. Neither hint promises a list of virtual callers; `class show` still accepts names, not table addresses.
  The primary address point is read from a zero offset-to-top and same-class local typeinfo header within the first 64 words of that object; virtual-base offset prefixes are not mistaken for the header. An unseen or ambiguous header leaves `address_point: null` and the note says it was not decoded, while retaining the known class-layout command.
  Attribution requires a complete supported identity census: any capped, malformed or unread symbol/string table discards all class hints, including earlier matches from another table. Invalid ordinary section indexes and `SHN_XINDEX` refuse attribution; the helper deliberately does not decode extended indexes, even with a companion `SHT_SYMTAB_SHNDX` table. Every defined `_ZTV` must have a supported object type, positive body extent and valid file-backed owner; zero-size/short aliases, NOTYPE, absolute/common, or unresolved owner/bounds refuse attribution rather than disappearing. Undefined imports are known non-definitions. Relevant local definitions are selected among all same-raw-name symbols, not an arbitrary GOT/import alias.
  Name navigation additionally requires bounded native symbol/function populations (at most 65,536 each), no other local object under the full name, and an exact canonical class-registry record at the ELF object head. A second marker is allowed only at the header-proven primary address point, never merely because it lies inside an extent or is another ELF-defined head. When all refs are outside known extents, no per-vtable symbol/header work or registry proof runs; a positive candidate can require the existing bounded registry scan.
  Other ELF vtable objects (#1018): a listed location inside a sized `_ZTV` or `_ZTC` (construction vtable) object that does not qualify for class navigation is reported in `callee_data_ref_objects` with the object, BN's label (`construction vtable for B-in-D`) and its extent, by symbol size only, and its text line keeps the `bn xrefs` command. No slot number is given: nothing here establishes which header in the object governs an entry. `callee_data_ref_census` says why no extent could be read: no `.symtab` (a stripped file; only `.dynsym` exports are visible), a relocatable object (`ET_REL`, whose symbol values are section offsets, not addresses: no label is computed), no section headers, not ELF, or an unread, malformed or over-budget table.
- Construction sites in `class show` are ordered by numeric call-site address before the display cap, so the displayed prefix is stable across bridge sessions. A shown site whose first argument is, through BN's SSA def-use and plain copies only, the result of a global `operator new`/`new[]` call (`_Znwm`/`_Znwj`/`_Znam`/`_Znaj`, nothrow and aligned forms) with a constant size carries `allocation_request: N`, `allocator` and `allocation_at` (text: `ctor-call @ <site> (this = _Znwm(0x38) @ <alloc>)`). It is what that ONE site asked for, never a class size: the site may construct a derived object, allocate trailing storage, or call a constructor folded with another class's. The card's `size` comes only from a type BN has defined (`size_reason: "no_defined_type"` otherwise), and nothing in bn turns an allocation into a class width.
- `evidence surface` surveys constructors, pointer tables, and executable addresses BN may not have made functions: those referenced from data, and those whose address code takes (an `adrp`/`add` or `lea` storing a handler into a struct field, `sa.sa_handler = handler`, shows as `&data_<addr>` in the decompile). A code-referenced candidate's `provenance` is `code_ref:<function>@<site>` and `referenced_from` lists the sites; a site that only loads from the address, computes a jump-table base, or is an aarch64 `adrp` whose consumers only add a nonzero page offset (the page base `bn xrefs` also drops), does not nominate it. When a referencing function's MLIL stores the address itself, `stored_to` lists those stores as BN writes them (`stored to [arg1 + 0x10] in <fn> @ <addr>`), at most four, with `stored_to_total` counting them all (text adds `+N more store(s) of this address not listed`); that is where the address is written, not a claim about what the field is. It is read-only; candidate `code_likely` and `decode_depth` are triage signals, not proof. Verify a candidate with `bn disasm <addr> --linear 16` before `function create`: `next_action` carries that command for the first listed candidate, with the invocation's `-i`/`-t` routing added, so it runs as printed with several targets open: a candidate is outside every function, so plain `disasm <addr>` refuses it. `evidence init` handles pointer width, endianness, and ARM/Thumb normalization. `evidence table` distinguishes pointer arrays from mixed records; declare record stride and pointer or scalar fields only when the layout is known.
  - Vtable labels (#1017): a candidate table's `elf_vtables` lists each defined ELF `_ZTV`/`_ZTC` object its entries lie in, from the symbol's `[st_value, st_value + st_size)` only, with the number of entries inside and the first of them (no slot number). `entries_outside_elf_vtables` counts the rest, and `extends_past_elf_vtable` flags a run that continues past an object's `st_size` -- the scanner merged that vtable with whatever follows it. No header or filler rule is used: a record shaped like an Itanium header (`{0, &typeid(T), fn, ...}`) outside every object stays unlabelled. Stripped files get no labels, and `summary.vtable_labels` says why. `--hide-vtables` hides tables whose every entry lies inside such objects (counted in `summary.vtable_tables_hidden`); their function-less slots stay listed as candidates.

- `evidence calls <reg-fn> --arg-struct N --field name:type@offset` reads a stack-built descriptor at each registration call. `ptr` resolves a callback/data symbol when possible; unknown, computed, and merged values remain marked. - `trace <caller> <call-addr> --arg N` follows MLIL SSA backward within the caller. `--interprocedural` follows return values into internal callees; it does not map callee parameters up into callers or follow output-pointer writes. A step whose value is the address of a local (`x1 = &var_68`, a stack array or struct) ends at an `address_of_local` frontier naming the local, with a caveat per local: `trace` does not follow the stores into it. When the traced argument itself is that address (directly, through register copies, or through a phi whose every arm is the same local), a hint prints the `bn taint backward -f <fn> --sink arg:<callee>:<n>` that slices those stores and a `bn taint forward` for an output pointer: `--source call:<callee>` when the callee's model declares it writes that argument (`*arg:<n>`), else `--source arg:<callee>:<n>`. - `target info` states `needed_libraries` (DT_NEEDED), `soname`, `rpath` and `runpath`. An `imports` row's `library` is the library its ELF symbol version requires (`.gnu.version_r`) or BN's own per-library namespace. A row bn cannot attribute that way keeps `library: null` with `library_note` ("no library attributed: bn names a library only from a symbol-version requirement it could match; the loader picks it at run time from DT_NEEDED"; on a target with no DT_NEEDED entry it ends "this target lists no DT_NEEDED libraries" instead); this describes what bn does, not whether the symbol is versioned. When the parser recorded a reason it did not read the symbol versions (a value out of range, also in `dynamic_section_notes`), the note adds "symbol versions were not read: <reason>". The listing names the DT_NEEDED list (`unattributed_note` on the envelope); bn reads no file other than the target. `library_source` says where a non-null `library` came from: `namespace` (BN's namespace) or `symbol-version` (`.gnu.version_r`). `--summary` states the same reason under `unattributed:` (`unattributed_note`). A dynamic-section value that is out of range for the file (a corrupt or hostile entry size, a table past the end of the file) is skipped, not guessed around, and named in `dynamic_section_notes`.

`evidence table` never guesses relative jump-table encodings. Select
`--decode relative-int32 --base <address>` to read signed 32-bit offsets in the
target's byte order and add the same explicit base to each one. The base need not
be the table start. This mode defaults to 4-byte stride and width; `--stride`
can select spaced entries, but a width other than 4 and record fields are refused.
JSON retains each raw hex `value` and adds signed integer `offset` and hex
`decoded_address`; `target` and plausibility describe that decoded address.
A zero offset points to the base, not a null pointer. Omitting `--decode` keeps
the absolute-pointer interpretation, including under `--stride 4 --width 4`.

Before an unfamiliar large read, use `--estimate-output` to measure its output without emitting the body; then slice with `--limit`, `--lines`, or `--out`.

## Data-symbol pagination cost

`data symbols` defaults to 100 rows, but **every page rebuilds the full named-symbol population**: the bridge enumerates all DataSymbols and filters out unnamed ones again to compute the honest `total`. Only row construction and serialization are limited to the requested window. There is no population cache shared between pages; walking every page repeats the full scan under the shared read lock on every request and multiplies aggregate lock-hold cost.

For an index that needs every symbol, prefer one whole-set request:

```bash
bn data symbols --offset 0 --out /tmp/bn-data-symbols.json   # omit --limit: uncapped, one request
bn data symbols --offset 0 --limit 50000 --format json     # one large page; whole set only if total <= 50000
```

`--out` removes the default page limit, but an explicit `--limit` still wins and a nonzero `--offset` still skips rows. Read the artifact named by the output envelope. Programmatic callers can send op `data_symbols` with `{"offset": 0, "limit": "all"}` for the whole set; the response echoes `limit: null`. Omitting `limit` or sending `null` instead requests the default 100-row page, not the whole set; CLI `--limit` accepts a positive integer, not `all`. A single request still pays one full population scan and builds all requested rows while holding the read lock. Check `has_more` before treating a numeric-limit result as complete.

## JSON reads and coverage

Most collections use `{kind, items, total, offset, limit, returned, has_more}`. Inspect `kind` before selecting a container. Common leaves:

| Read | Rows or payload |
|---|---|
| `strings` | `.items[].value` |
| `function list` / `function search`, `imports`, `exports` | `.items[].name`, `.items[].address` |
| `sections` | `.items[].name`, `.start`, `.end`, `.length`, `.semantics` |
| `types` | `.items[].decl`, `.layout`, and aggregate `.members[]` |
| `local list` → `.items[]` | same list retained under `.locals`; rows carry `.local_id`; stack rows carry `.distance_to_next_slot` (slot pitch, not object size; the top negative slot measures to entry-SP offset 0 even when no slot is recovered there) |
| `local list --frame` → `.items[]` | one row per distinct stack offset: `.storage`, `.kind` (`local`/`saved_register`/`canary`/`return_address`/`caller_frame`), `.names`, `.distance_to_next_slot`, `.to_canary`, `.variables[].local_id`; top level `.canary_storage`. Canary evidence requires a full-ABI-word guard load and copy; TLS identity comes from architectural registers, not mutable local names. |
| `xrefs` | `.items[]`, with `.kind` and `.caller_function` per reference |
| `callsites` | `.items[].caller_static`, `.callee`, `.containing_function` |
| `comment list` | `.items[].comment`, `.scope` (`address` or `function_doc`) and `.written_this_session` |
| `tag list` | `.items[]`; `tag get` instead uses `.tags[]`; `tag types` uses `.tag_types[]` |
| `evidence function` | `.calls[]`, plus pagination metadata |

Addresses in JSON are hex STRING values such as `"0x401000"`; convert before arithmetic. `row_fields`, when present, lists the keys EVERY row carries; `row_fields_optional` maps the keys only some rows carry to the condition that sets them (`code_ref_count: "--with-xrefs or --probable-format-strings"`), so read those with `.get()`. A zero-hit read may have no schema for a kind without a declared schema.

**Absence requires a complete read.** Check `has_more`, caps, and scan notes. When the default page of 100 cut a listing short (no `--limit`, no `--out`), stderr carries `note: the default --limit 100 cut this page short (N of TOTAL); …` in every format, so a pipe or a JSON read still sees it. In particular, an import xref scan may return `items: []` with `truncated: true` and `scan_note`; text prints `note: the caller scan was TRUNCATED`. That means unknown, not zero callers. For high-fan-in `callsites`, `total: null` is a lower bound: inspect `total_lower_bound`, `scan_truncated`, `caller_scan_truncated`, and `caller_scan_note`. Either truncation flag prevents a complete-caller claim. A determined integer total must remain stable across pages.

`Client.collect` and both `bn-kernel` backends report callsite coverage from the final request's cumulative scan, not the first page or a sum of page counts. The scan starts at row zero and includes lookahead, so `callers_scanned` and `total_lower_bound` need not equal the number of returned rows, especially with finite limits, nonzero offsets, or zero-row probes. An exact `total` replaces the lower bound; `total_lower_bound` is then omitted. A terminal `has_more: false` can still accompany `caller_scan_truncated: true` and `total: null`: all discovered rows were exhausted, but caller enumeration remains incomplete.

For taint JSON, forward flows are `reached_sinks[]`, each with `.sink` and `.path`; backward results are `slices[]`, while top-level `sinks` repeats the query as written (`arg:sscanf:2` stays `sscanf`; the call's own rows name `__isoc99_sscanf` with `model: sscanf`). `sink_status[]` has one row per selected call site (`address`, `seeded`, `status`): `seeded` (sliced; `slices` counts its slices), `constant` (a value-role operand that is a literal: `scalar: {kind: constant, value}` and `destination_fit: "unproved"` -- a constant never proves the destination's capacity), `demand` (not seeded, but the operand has a pointer demand; see its frontier leaves), `unseeded` (could not be seeded; `note` says why), `truncated` (slicing hit the recursion limit; partial slices kept). On a zero-sink forward run, read `diagnostics.safe_to_report_all_clear`: weak seeds or unmodeled-call assumptions can withhold an all-clear even with no leaves or truncation. A true gate only supports absence of modeled sink flow under that analysis, not absence of bugs. A backward run reports `diagnostics.safe_to_report_complete_slice`; it is false whenever a frontier leaf remains, the run was truncated, or any slice origin (any entry of `origins[]`) has kind `unresolved` (counted under `diagnostics.frontier.unresolved`). A slice that reaches `p = &local_buf` at any offset (`p = &line + off`, or a sink handed `&local_buf` directly) continues through every writer of the buffer on the sink's memory chain, beside the offset -- a modeled call that filled it (`snprintf`, `strcpy`, `memcpy`, a `read`-style source) to that call's operands, including a nested local buffer read at that call's own memory version (`strcpy(buf, &other[i])` walks `other`), a plain store such as a `buf[n] = 0` terminator, a store through a phi'd loop cursor built on `&buf`, a modeled call that reloads the slot `&buf` escaped into, a `memset`/`bzero` literal fill, and a length argument of a bounded fill (`memcpy(buf, lit, n)`); a parameter or source copied in by an older writer outranks a later literal append as the origin. A by-name read of an address-taken local is that local's contents whether it is bare (`n = bits @ mem#3`) or under a conversion or arithmetic (`zx.q(bits @ mem#3)`, `sx.q(...)`, `low_part(...)`), so a helper handed `&bits` is one of its writers. Which bytes stores cover -- reported as facts, never as a certified proof -- is the next paragraph; no call covers a byte. An `address_of_local_unresolved` leaf names the buffer whenever the walk could not account for its bytes: an unmodeled call that received `&buf` or ran after `&buf` escaped to memory, a consumed byte that no visible store writes on some path (a conditional or loop-only fill, an indexed store, a call fill, an escape of `&buf`, a pointer that may point at another local, a `{}`-modeled call), a writer input that is neither a literal nor a local (a constant address into read-only data is a literal; the address of a `.data`/`.bss` global, or an element of one at a variable offset such as `g_hosts[i]`, is a leaf with origin `global`), a store through a pointer the walk cannot resolve (a reload after `&buf` escaped), a modeled call whose out-argument pointer cannot be resolved while `&buf` is escaped, or a memory chain past the walk budget (`stats.truncated` with cause `memory_chain`). A `{}`-modeled callee handed `&buf` is named in `assumptions`: the slice trusts that it writes nothing tainted.


**Result envelope.** Every leaf's human sentence is `detail` (no leaf carries `note`), and every leaf `function` is an object `{name, display_name, address}`. `run_params` echoes the configured knobs, never what was reached (`stats.max_depth` is the deepest depth reached): forward `max_depth`, `max_iters`, `unknown_call`, `sink_classes` (the opt-in `--sink-class` list); backward `max_depth`, `unknown_call`; both `resolve_map` (`{path, entries, matched, unmatched}`, or null without `--resolve-map`) and `models` (the overlay rows actually merged -- `--models` or `$BN_TAINT_MODELS`, labelled by `via` -- never the builtin DB or an overridden env file). `resolve_map.matched` lists the pins that routed an indirect call or jump the walk could not resolve itself, or through which a `call:`/`ret:`/`arg:` locator anchored its source or sink at an indirect call, and `unmatched` the rest, so a pin keyed to the wrong address (a thunk, a stale build, a direct call the walk follows to its real target, an indirect call the walk never reaches) is visible rather than silently inert. Each `--resolve-map` value must be a non-empty JSON list of targets (`{"0x401230": ["0x401176"]}`); a bare string or number target is refused (exit 2). Zero-sink forward `diagnostics.tainted_values` counts tainted SSA values, null when the walk did not finish (a recursion unwind measured nothing); `diagnostics.propagated` (bool) says whether the result itself shows the seed reached anything: a recorded last use, more than one tainted value, or a frontier leaf other than the kinds the seed step can emit on its own (`seed_unused`, `source_seed_misanchored`, `indirect_call_unchecked`, `format_destination_unrecovered`, `scanf_arity_residual`, `format_unchecked`, `abi_provenance_budget`) and the `analysis_truncated` unwind marker.

**Truncation.** A cut is recorded in `stats.truncated` + `stats.truncation_cause` (a list), in the frontier leaves it left, and, on a zero-sink forward run, in `diagnostics.truncation_cause` -- never under `assumptions`. Text renders each cause as itself with its remedy; a cause this table does not know is printed verbatim (pointing at `stats.truncation_cause`), never as `@depth N`.

| cause | what was cut | remedy |
|---|---|---|
| `max_depth` | interprocedural depth bound; the call it stops at is assumed to return taint. A deeper run that descends the call is NOT guaranteed to reach the same sinks: the walk models the body instead of the assumption. One known shape where they diverged is fixed -- a helper that writes through `g + i` into a static buffer and returns it (see "Writes at a runtime index") -- so compare runs at two depths before reading a sink's absence at the deeper one as proof | raise `--max-depth` |
| `fixpoint_exhausted` | intra-function iteration budget, fixpoint unconverged | raise `--max-iters` or narrow the source |
| `recursion` | Python recursion limit (likely unresolved cycle); findings before the unwind are kept | internal, no flag; narrow the seed (see `analysis_truncated`) |
| `caller_cap` | not every caller site was followed | internal, no flag; narrow the sink or follow the sites `caller_sites_truncated` names |
| `memory_chain` | memory-chain budget while proving a local buffer's writers | internal, no flag; seed closer to the sink (see `address_of_local_unresolved`) |
| `abi_provenance_budget` | argument-register provenance scan ran out of blocks before a call | internal, no flag; narrow the seed or read the call's disassembly |
| `global_reference_budget` | function or reference-sweep budget searching for readers of a tainted global | internal, no flag; audit the references `global_memory_continuation` names, or seed inside a consumer |
| `global_object_extent` | a tainted global's object extent is unproven | `data retype` as the leaf advises, or narrow the seed |
| `global_object_search` | search for the object enclosing a tainted global write | internal budget, no flag |
| `global_object_layout` | walk to a tainted global's next named neighbour | internal budget, no flag |

`global_memory_continuation` fields: ONE leaf per tainted global, however many calls it stayed live across -- `sites[]` lists each `{address, callee, descended}` (the leaf's own `address`/`callee` are the first); `global` `{address, label, written_offsets}` (`label` is the global's data-symbol name, else `glob_<address>`; the keyed offsets, ascending, the union over the sites, so an interior write is not read as the whole object); `callee`; `references[]` rows `{name, display_name, address, at, access, offset, offset_known, seed}` (the union over the sites; `unverified_overlaps` counts the `overlap_unverified` rows of that union, so one candidate seen from several calls counts once) -- `access` is `load` or `call_arg` (proven reads; `reads_proven` is true when any row is one), `return`, `unknown_call_arg`, `unclassified`, or a scan bound `scan_budget_exhausted` / `pointer_depth_exhausted` / `param_budget_exhausted`; an `offset_known: false` offset is unknown, not the base; `seed` seeds the reader's input -- the variable a load fills (`var:<name>`) or the argument of a call that is not a sink operand of its model (`arg:<callee>:<n>`: a copy's source, a parameter of an in-binary callee) -- never a sink's own argument, which would only re-find that sink, else null; `reachability` `{status: complete|truncated, cause, causes, functions_examined, function_budget, unexamined_references, unexamined_reference_sites, unexamined_references_total, unread_bodies, unresolved_calls}` (merged over the sites: truncated when any search was, every cause, the most functions examined; text names the first unexamined reference); `call_descended` (the call itself was descended with its tainted args); `reseed` (a runnable `bn taint forward` command into the first reference with a seed, absent when none has one). A reader that reaches the object through a writable pointer global initialised to it (`char *p = g;`) is a reference of the object -- every such pointer global BN lists a data reference from, however many there are. Reachability causes: `depth_budget` (aggregates as `max_depth`), `function_budget` / `reference_sweep_budget` (`global_reference_budget`), `object_extent_unproven` (`global_object_extent`), `object_search_budget`, `object_layout_budget`, `thunk_chain_budget` (`global_veneer_chain`), `pointer_scan_budget`, `pointer_return_depth`, `parameter_scan_budget`, and the non-budget `unresolved_thunk`, `unresolved_call_target` (pin with `--resolve-map`), `unread_callee_body`.

`unread_callee_body` fields: `callee`, `skip_reason` (raw: oversized body vs failed lift), `modeled` (a model matched, yet the body stays unread), `via` (the modeled name it went through, or null), `tainted_args`, `abi_recovered_args` (args proven from the ABI register, `[]` normally). `caller_sites_truncated` fields: `function`, `callers_total`, `callers_fully_followed`, `callers_partially_followed`, `callers_unfollowed`, `callers_dropped`, `demands_total`, `demands_unfollowed`, `reasons` (`{reason: count}`), `unfollowed[]` (the first 16 rows in address order; `unfollowed_total` counts all of them), `partially_followed[]` (`{address, followed_params, unfollowed_params}`); `diagnostics.frontier.dropped_callers` sums the dropped caller references (plus `dropped_callers_unmeasured` when a leaf had no readable count -- the sum is then a lower bound).

Forward `indirect_call_unresolved` fields: `dest_expr`, `il_text`, `tainted_args` (every argument index that reached the call, merged: one leaf per call site, however many argument contexts or visits reached it), and `resolve_map_template` -- the `--resolve-map` document for this site, `{"<call address>": ["TARGET"]}`, with `TARGET` (an address or a function name) left to fill in. When unpinned indirect calls are the only unresolved call frontier, `next_action` prints that document for the first 8 sites and the re-run as a template (`--resolve-map FILE`). A backward `indirect_call_unresolved` (a value an indirect call returned) carries `address` and `il_text` only. `field_load_unresolved` fields: `base`, `offset`, `width`, `il_text`, and -- when the load's memory chain was walked (an exact slot) -- `candidate_writers[]`, the calls on that chain back to a covering store or the entry that may have written the bytes, each `{address, callee, handed_object}` with `callee` the `{name, display_name, address}` of a direct target (null for an indirect call) and `handed_object` true when an argument is the loaded object (a pointer rooted where the load's address is, or the global's address); those calls lead, then the rest in walk order back from the load. The first 8 are listed, `candidate_writers_total` counts all, and `candidate_writers_complete` is false when the chain walk hit its version budget. `detail` names those calls by display name (raw under `--mangled`), never by MLIL text.

`source_seed_misanchored` fields: `callee`, `arg_index`, `reason`, `seed` (`arg`/`call`), `suggested_source`, `address`. When the unkeyed buffer pointer is a parameter of the seeded function itself (a read wrapper `fill(fd, buf, n)` -> `read(fd, buf, n)`, or that parameter as the BASE of a sum: plus a constant, or plus a value of unknown origin only when the parameter is pointer-typed -- `c->buf + have` with an integer `have` names no parameter), the leaf also carries `buffer_param` (`{function, index}`), `callers_total` (distinct direct callers) and `caller_seeds[]` -- the first 5 callers by callsite address, each `{function, address, reseed}` with `function` the caller's `{name, display_name, address}`, `address` its lowest callsite, and `reseed` a runnable `bn taint forward -f <caller> --source arg:<function>:<index>`; `next_action` prints those commands. With no `caller_seeds` (no direct caller, or no parameter buffer) `next_action` keeps the marked template advice: seed a value read from the buffer (`var:VAR`) or the parser that consumes it. A forward `ret:`/`arg:`/`call:` source naming a callee the function does not call is refused (exit 2) with the functions that call it directly -- those this function itself calls first, then by callsite address, at most 5 plus a count -- each with its `-f` address, before any `--resolve-map` advice for the function's indirect calls.

**Text.** Forward `global_memory_continuation` leaves render as one block per global: the call sites it stayed live across, its readers (the first four, then a count), the reachability-truncated qualifier, and one follow-up -- the leaf's `reseed`, else `bn xrefs <global>`; `--verbose` adds the `detail` prose. Continuation blocks are never folded into the frontier's `... and N more group(s)` elision, which counts only the groups it hides; `--verbose` renders every group with no elision. Forward frontier rows wrap at the terminal width (`$COLUMNS`, the tty, else 100); a printed command is never split, and its code-span fence is one backtick longer than any backtick run inside it (a selector may contain one), so take the text between the matching fences and shell-split it. A non-empty `run_params.resolve_map.unmatched` prints one `resolve-map (<path>): ...` line naming the unmatched pins. Taint `--estimate-output` help and spill advice both say no flag slices taint output (`--max-depth` bounds the analysis, not the output) and point at `--out`.

**Literal pointer sinks.** A sink that reads through a pointer is never complete, a string literal or other read-only literal included: `popen("ls")` still carries a blocking `pointer_demand_not_certified` leaf, whose `literal` object lists `address` and `segment_writable`. A read-only segment describes the object; it does not complete the slice.

**Backward slices are paths.** Each `slices[]` row is one distinct path -- the same steps through the same functions -- from the origins it ends at to the sink. `origins[]` lists every origin of that path (several origins in one function share its def-chain walk); `origin` is the first of them, and `origin_names` maps each origin's `function` address and `callee` to `name`/`display_name`. Two caller sites that reach the same origin are two rows: the call site is part of the path, and its `passed as arg N to <fn>` step names it. Text prints one line per path followed by `origin: …` or `origins (N): …`, each origin as its kind, its callee, variable or constant value, and `in <function>` by display name (raw under `--mangled`).

Every origin carries `function` (the address of the function it was found in); its `kind` is one of:

| origin `kind` | meaning and fields |
|---|---|
| `parameter` | a formal of the function (`index`, `var`; `via_spill: true` when a stack slot holding the incoming value was read as that formal); the caller ascent continues from it |
| `entry` | a value live at function entry that is neither a formal nor an unmapped argument register -- an uninitialised local or callee-saved state (`var`); no caller is followed |
| `abi_mapping_unbound` | a register's entry value no formal of the recovered prototype is bound to (`register`, `var`); paired with the leaf of the same kind |
| `source` | the return or fill of a modeled source call (`callee`, `address`, and `model` when it differs from `callee`) |
| `call` | a call the walk stops at: one with no model deriving its return from an argument, or a modeled fill or derivation whose inputs are all literals (`callee`, `address`, `model` when it differs) |
| `constant` | a literal value (`value` when it is an integer, `var`); in the caller ascent, the constant argument a caller passes, with `function` that caller |
| `global` | bytes read from a writable global any function may set (`address`, `buffer`); paired with a leaf naming the global |
| `indirect_call` | the return of an indirect call whose target was not resolved (`var`, `address`, `function`); paired with an `indirect_call_unresolved` leaf |
| `address_of_local_unresolved` | bytes of local buffer `buffer` the walk could not account for; when calls may have written them, `callee` (the first) and `writers` (rows of `address`, `kind`, `callee`) |
| `pointer_object_unresolved` | the same for the object behind pointer `pointer`, with `callee` and `writers` for calls that may have written it |
| `object_extent_unknown` | stores cover a consumed region of `buffer` the walk cannot bound (`cause`: `outside_object` or `offset_unknown`; `region`, `unproven`) |
| `field_load_unresolved` | loaded bytes the walk could not account for (`base`, `offset`, `width`) |
| `unresolved` | the def-chain ended without reaching an origin (`var`, `function`); when `--max-depth` cut it, `cause` (`def_chain_budget`), `budget` and `unwalked`. Counted against the all-clear |

**Caller ascent (`caller_sites_truncated`).** A formal the slice bottoms out at ascends into its function's callers. At most 16 distinct call sites per function are followed -- a site is its address and the function it is in, so a site BN lists twice is one site and two overlapping callers sharing a call instruction are two -- chosen in address order, so the followed subset is the same for a raw ELF and its saved `.bndb`. Every caller reference the ascent did not follow -- a site past that cap (`caller_cap`), past `--max-depth` (`max_depth`), a site it could not walk (`caller_unknown`, `caller_unlifted`, `no_call_instruction`, `arity_short`, `constant_address`, `argument_not_trackable`), a stored or handed-on address (`indirect_reference`), or the process entry stub handing the function to an imported C-runtime start routine as its main callback (`crt_entry`: `_start` passing `main` to `__libc_start_main`/`__uClibc_main` as operand 0, with no other use of the address in the entry function; a static or in-binary start routine, another operand or a second use stays `indirect_reference`) -- is a row of that function's one `caller_sites_truncated` leaf: `callers_total`, `callers_fully_followed`, `callers_partially_followed`, `callers_unfollowed`, `callers_dropped`, `demands_total`, `demands_unfollowed` and `reasons` count exactly, `unfollowed` lists the first 16 rows (`address`, `caller`, `param`, `reason`) in address order and `unfollowed_total` counts all of them. The configured cuts, `caller_cap` and `max_depth`, are also run truncation: `stats.truncated` and the cause in `stats.truncation_cause` (a `max_depth` cut's depth is `stats.max_depth`, the deepest caller depth the ascent reached) -- never an `assumptions` entry. A `crt_entry` row still withholds `safe_to_report_complete_slice` (what the runtime passes is not proven), but it has no caller in the binary to slice from, so it adds no caller advice: `next_action` is the run's other frontier advice, or, when none remains, names the function the C runtime enters and says its formals are what the process was started with (program inputs) before asking you to classify each origin.

**Forward walk bounds.** A `global_memory_continuation` is decided per (call site, tainted global), after the function's fixpoint converges, and the sites of one global are reported as one leaf. Every such decision in one request draws on a shared reference-sweep allowance, spent only on bodies that can hold a pointer to the object: one that names it (or an object that may enclose it, or a pointer global initialised to it), or that calls something which can return it; any other body is not scanned. Once the allowance is spent, no further body is classified: each unfinished sweep stops and says so -- the leaf's `reachability.causes` carries `reference_sweep_budget` (aggregate `stats.truncation_cause`: `global_reference_budget`), the referencing functions it never reached are listed as unexamined, and a body left unclassified is cited with access `sweep_budget_exhausted` -- unknown, never clear. A scan already running when the allowance runs out finishes under its own bound (`pointer_scan_budget` stays reported as such). A walk that unwinds on Python's recursion limit keeps the sinks and leaves it had found and adds an `analysis_truncated` leaf (`cause: recursion`) whose `depth` is where it was cut: at depth N > 0, `--max-depth N-1` finishes the region above the cut; at depth 0 no `--max-depth` avoids it, so seed past it from a callee. A cancelled request -- `cancel_request`, a client timeout, or (Linux) a client that hung up -- stops at the next function visit or sweep step and answers `ok: false` with `status: "cancelled"` and `observed: {cancelled, functions_visited}` (exit 2).

**A client timeout's outcome.** When `BN_REQUEST_TIMEOUT` expires the CLI sends `cancel_request` and, for an op that checks for cancellation (`polls_cancel`), keeps listening briefly for the outcome. Its error (exit 2; under `--format json` also the envelope on stdout) carries `observed`: `timed_out: true`, `request_sent`, `cancel_sent`, `polls_cancel` (null when the bridge did not say), `cancel_outcome` (`cancelled`: the bridge stopped the op; `finished`: it completed before the cancel took effect, result discarded; `no_answer`: it had not stopped when the CLI stopped listening; null: the CLI did not listen) and `cancelled`. When the bridge stopped the op, the envelope's `status` is `cancelled` and `observed` keeps the bridge's own fields (`functions_visited`); otherwise there is no `status`.

**Partially tainted structs (forward).** A store into one field of a local struct taints that field only, and the struct handed by address carries just those bytes. A member holding the address of a place in the SAME struct (`s.active = &s.slots[0]`) is followed: a load through it reads the field it lands on, so a tainted member reached that way is a flow, a clean one is not. When the place it points at is not one constant offset (`&s.slots[k]`), the load is a `field_load_unresolved` frontier, never silence. A clean value stored through a pointer to such a struct does not taint the whole object. A call is judged on every set of fields the struct carries into it as the function's fixpoint converges: a field stored after the call that reaches it again over a loop's back edge is handed to the callee on the next pass, and a sink the earlier pass already reached is still one flow.

**Reader sweep economy (forward).** Whether a body can see a tainted global is decided once per (body, global) per request, from the reference index and BN's caller edges: the bodies that name the object's storage and the callers of any that may return a pointer to it. Below a call from which BN's recorded call edges reach none of those bodies, the search walks the edges without lifting anything -- unless a body BN skipped, flagged a thunk, or left with an unresolved call site is in the way, which is lifted and classified as before. The remaining cost of a continuation is classifying the bodies that DO name the object; on a target where dozens of functions reference one tainted global, that classification is the run's own breadth, not overhead.

**Backward coverage: consumed regions, store facts, no certification (#931, #933).** **The rule: a sink that reads through a pointer is never complete; the leaf lists what it may read.** Neither a call nor a store certifies a buffer's bytes, so every pointer-consuming sink -- a string literal included -- carries a blocking `pointer_demand_not_certified` leaf whose `objects` lists every object the pointer may read, each described on its own (`kind`: `local`, `global`, `got_or_extern` with its GOT `slot`, `literal` and `constant_address` with their `address` and `segment_writable`, `loaded_pointer`, `parameter`, `returned` with `may_point_into` and a `note` when BN recovered no destination argument, `unknown`). Each object's `offset` is where the consumer's pointer lands in it (`p = b + 8; popen(p - 8)` reads `b` at 0), or `null` when a non-constant step makes it unknown. The description never decides completeness. **Whether a sink reads through its argument is the sink model's role for it, not BN's typing:** command, path, format and string classes, a format-gated sink's `format_arg` (scanf's format) and a `*arg:N` the model reads are pointers; `alloc_size`, `overflow_len` and `fortified_overflow` arguments are values; a mixed buffer-and-length sink (`write`, `send`, `fwrite`, ...) names its buffer in `sink.pointer_args`. The role holds for an argument recovered only from its ABI register (`recovered_from_register: true` on the leaf) and for an indirect call pinned by `--resolve-map` or a value set (the locator's callee is the pinned target). **An argument is a value only when a model says so** (the builtin DB or a `--models` overlay): an argument no model gives a role -- an ad hoc `arg:helper:N`, whatever BN typed it (integer, struct, union, float) -- is walked as a pointer demand and carries a blocking `sink_role_unknown` leaf naming the callee and argument (`callee`, `arg_index`). Its `declare_value_role.entry` is an overlay entry: the callee's current model (an overlay entry replaces the whole model) with the value role merged in -- a new sink when it has none, the argument added to its sink's `tainted_args` (its pointer arguments named in `pointer_args` under a non-value class) when it has one. `placeholders` names each UPPER-CASE value to replace (`VALUE_CLASS` with a value class for a new sink) and `template` is true when there is one; with none the entry is concrete. Save it as a file and add `--models FILE` to the same command you ran. The role is decided before the no-def-chain exit: an argument the sink reads through that has no backward seed (`popen("ls")`, a fixed address) is an incomplete answer with its leaf, not a refusal, and a multi-sink query is complete only when every selected sink is -- a sink it could not seed at all adds a blocking `sink_unseeded` leaf. A value sink (a `malloc` size, a `memcpy` length, even a pointer-typed value cast into one) has no demand and works as on base. The leaves below add per-object detail. A local buffer a consumer reads through a pointer -- the operand an `arg:` sink locator selects, a fill's source -- is checked over its *consumed region*: from the offset that consumer's pointer points at to the end of the object. The offset is the selected operand's own, never another argument that reads the same value (`strcpy(p + 8, p)` with `--sink arg:strcpy:1` reads from 0), carried back through copies, constant arithmetic and phis (`p = b + 8; popen(p - 8)` reads from 0, `p = (char *)&s; popen(p + 4)` from 4); it is never rebuilt from the definition the walk happens to reach. A load or a by-name field read consumes exactly its own bytes. Bytes after the end of a member are part of the region, because a forward reader of an unterminated member runs into the next one. The walk reports which bytes **plain stores the slice can see** write on every path: a store at a must-alias offset writes its own width, a whole-variable store writes the variable, and a `__builtin_memset`/`__builtin_memcpy`/`__builtin_memmove`/`__builtin_strncpy`/`__builtin_strcpy` that BN outlined from inline stores counts as stores only when its own LLIL is one contiguous store run of exactly the stated length from one base. **These are facts, never certification: no region proof from stores makes a slice complete** (review round 3). Covered bytes do not establish a NUL terminator either. When stores cover every consumed byte the slice keeps the writers' origin and a blocking `region_store_proof_not_certified` leaf with `stores_cover` (`[start, end)`), `region` and `unproven`, and `next_action` prints `bn il <fn> --view mlil` to check by hand that the consumer reads only those bytes and that the local is the whole object. A demand before the object or past its end (`p = s.cmd; popen(p - 12)`; never clamped into it) or at an offset that is not one constant on every path (a moving cursor, phi arms that disagree, a reload) is an `object_extent_unknown` leaf (`cause: outside_object | offset_unknown`). Why the store proof was cut, for the follow-up: across three review rounds it was forged by an anchor on the wrong argument, by an outside-object demand clamped into the object, by BN's stack fragments of an untyped object standing in for the object, by a name-only `bn local rename` making such a fragment user-defined, and by an upper-half `read` into the real object that the fragment's proof left out of the slice. **Cost:** no backward slice through a local buffer's contents is ever complete; the stores and the region are still reported. K's exact-slot scalar loads (`_load_writers`: a definite store to the exact slot a load reads) are unchanged. **No call proves a byte** either -- not `snprintf`, `strcpy`, `memcpy`, `read`, `fgets`, `fread`, an `_chk` variant or an append: a requested length is not what a read delivered, an append does not initialise what precedes it, and a formatter can fail. Such a call is still a writer whose inputs are walked, so its arguments remain in the slice as candidate origins, but the buffer leaves an `address_of_local_unresolved` leaf with `region` (`offset`, `size`), `unproven` and `calls` (the raw callee names). The same holds on every consumer path: a pointer a call returned (`p = fgets(c, 64, f); write(1, p, 64)`) reads any object the call was handed to write -- a local is checked as a whole, a heap allocation or a pointer parameter is a `pointer_object_unresolved` leaf, a writable global buffer or global struct member (`fgets(g_buf, ..)`, `fgets(g_req.cmd, ..)`) is the same `global` frontier as consuming that global directly, and any other object it was handed -- a global reached through the GOT (`MLIL_IMPORT`, a preemptible global in a shared object), a loaded pointer, any expression the walk cannot resolve to a local -- is a `pointer_object_unresolved` frontier by default (a consumer reading through a GOT-loaded address directly gets the same leaf) -- and a pointer with no local behind it -- an allocator's or unmodeled helper's return, or a pointer parameter -- is a `pointer_object_unresolved` leaf: its writers in the function are walked (`b = malloc(64); strcpy(b, host); popen(b)` keeps `strcpy` and `host`), but the walk knows neither the object's extent nor what it held before. These rules apply to a value BN types as a pointer; a modeled source's own returned buffer (`getenv`) stays its origin. To check a call-filled region by hand, run the `bn callsites <callee> --within <fn>` the leaf and `next_action` print -- it shows the call with its arguments and the instructions around it -- and confirm the destination and length cover the consumed bytes on every path; a stated length still does not prove a short read filled them. Call-write extents are a separate follow-up. When the bounded escape solve converges, an escape at the bottom of a loop applies to calls in subsequent iterations. An exhausted solve withholds completeness, but the escape facts of the subgraph it did discover are still solved to a fixed point: a call that runs after `&buf` escaped stays a named frontier beside the `memory_chain` leaf, including a loop-carried one (`while (n--) { compose(); stash = buf; }` after a long prefix; #1034 item 3).

**Receive-buffer coverage (#1041 item 1).** Which pointer a callback receives is not tracked. When a `call:` or `arg:` source seeds a buffer its model fills (`recv`, `read`, `fgets`, the scanf family, ...), the only callback check is a gate in the **source function**: each indirect call there that bn did not resolve (not direct, no `--resolve-map` entry, no value-set target) and that can run after the receive is an `indirect_call_unchecked` leaf. Unknown reachability counts as reachable. The leaf withholds the all-clear even when the call is unrelated to the buffer. System calls are not counted. Pinning a target with `--resolve-map` makes the walk descend into it, but does not show that it receives the buffer. The gate does **not** cover other copies of the receive pointer, indirect calls inside callees the walk enters, `--resolve-map` or value-set targets, or computed jumps (tail transfers BN lifts as an MLIL `jump`). So every all-clear from such a buffer-filling seed carries `diagnostics.all_clear_caveats` (text: a `not covered:` line under the gate) naming those gaps. The list is empty for scalar `arg:` seeds (`arg:recv:0`), `param:`, `var:` and `ret:` sources. Check the gaps by seeding the buffer with a `var:` source, or by hand.

**Stash identity (#1034 items 1-2).** Slot identity is exact: two addresses are the same slot only when both are built by value-preserving steps (an SSA copy, a pointer-width variable read, a constant offset) on the same root -- a stack local, a constant address, or one SSA value. A narrowed or extended address (a store through `slot#0.edi`, any conversion) or a phi-rooted loop cursor is never the same slot as the full one. A pointer reloaded from memory is `&buf` only when one pointer-width store of `&buf` to that exact slot reaches a pointer-width reload on a straight memory chain, with nothing in between that may write the slot (a call, a phi, a store that overlaps it or may alias it); writes through such a reload are named writers, and a plain store through one counts its bytes as stored (a fact, #931; a call through one counts none). Otherwise a constant slot that a pointer-width store set to `&buf` on some path is remembered per memory version; a write through a reload of it is named as a possible writer (a step, its inputs possible origins) but never covers the buffer. Every write that may reach a remembered slot forgets it: a store to an overlapping constant address, a store through a pointer the walk cannot pin, and every call -- no model enumerates all of a callee's memory writes, so no call is proof that a slot survived. A store through the address of a local, or through a reload proven to be `&buf`, cannot reach a global slot. A value that only may alias the buffer never makes a slot remembered. `&buf` escapes at a store of a value that may alias it and at any call handed such a pointer: the callee may retain or plant it (strtok_r's save pointer, strtol's end pointer), so from there on any reload -- through a pointer or of an address-taken local by name -- may alias the buffer. Each LOAD is judged at its own memory version, so a pointer read before the first such escape stays unrelated even when it is copied through another slot afterwards. A narrowed reload (`(char *)(uint32_t)stash`) or any other conversion of the pointer is only a may-alias: writes through it are disclosed and cover nothing. After `&buf` escaped, a write through a slot whose value is neither proven nor remembered is an `address_of_local_unresolved` frontier.

**Loads (#1041 item 2).** A backward slice through a value read from memory -- a bare LOAD or one under a conversion such as `sx.q([p + 0xc].d)` -- follows the writers of the loaded bytes on every memory path, never the pointer they were loaded through. Bytes are matched by the exact slot identity above; a load whose address is not exact (lossy, phi-rooted, a pointer plus a variable index) walks its pointer and index and leaves a frontier; a constant table at a variable index or offset -- including `[(i << 3) + table]`, which keys on the scaled index -- walks the index and is a frontier: `field_load_unresolved` for a read-only table, a `global` frontier leaf naming the table for a writable one (an index walked to a parameter keeps that parameter as the slice's representative origin; the leaf still makes the slice incomplete). Its bytes are never taken as the binary's own, even for a bounded index wholly inside a non-writable segment, because the loader may have written them (an IFUNC or external-symbol relocation under `DT_TEXTREL`, an `IRELATIVE` entry) and section semantics do not prove immutability. That is a known precision cost: `malloc(readonly_sizes[i & 3])` is incomplete, including at -O0 where the old pointer walk called it complete. A store covering the loaded range is an origin. A store of another width or offset that overlaps it is walked, and the path continues for the remaining bytes. A store through another pointer or an inexact address is walked too, but may alias, so it leaves a frontier: two pointer values are never assumed distinct, while distinct stack locals, a local and a constant address, and non-overlapping constant ranges are. No call is proof that the loaded bytes were not written, and no call's write extent is trusted: models describe taint flows, not every memory write -- a failing read sets `errno`, `getenv` may copy into an internal buffer, `strtok` rewrites a delimiter, `stat` fills its struct, `strncat` appends at dst + strlen(dst). A modeled source that writes through a pointer (`recv`, `read`) is named as a possible producer and the path continues to earlier writers; any call leaves the load a `field_load_unresolved` frontier. Precise call-write extents were attempted in #1053 and left out after three review rounds. A path that reaches an unmodeled or `{}`-modeled call, another memory definition, or the function entry ends in a `field_load_unresolved` leaf whose `detail` names the cause. That includes a fixed-address load of writable or unknown storage that nothing in the function wrote (`n + mutable_length`): the global holds whatever was stored before the function ran. A fixed address is no exception, even in read-only data: with nothing in the function writing it, the load is a frontier (the global holds what was stored before the function ran), because read-only section semantics or a non-writable segment do not prove the file supplied the bytes. A load from a local buffer walks that buffer's writers like a sink argument built on it. BN's `*_STRUCT` forms (`p->lens+4.d`) are keyed by their field offset.

**A global behind a may-alias store (W02-10).** When a slice loads a value from a global and a store through a pointer the walk cannot prove disjoint MAY have written those bytes, the store is walked and named in the load's `field_load_unresolved` detail, but whatever produced that store's value never represents the slice: the origin is the load's own frontier, whose `base` is the global the sink read, never an anonymous pointer load further back. The store's value chain still contributes its own leaves and steps, but no origin -- not even a modeled source such as `recv` whose return the store wrote, and not on a recursive caller ascent either; only a formal it reaches still ascends. Such a call is a slice step that names it structurally: a backward call step carries `callee` (the called name) and, when a taint model judged the call, `model` (the matched key), beside `address` and `op`.

**Tainted globals (forward).** A writable global tainted by any write -- a direct store (`g = n`), a modeled copy (`memcpy(g, s, n)`) or a source filling it (`read(0, g, n)`), in the seeded function or one the walk descended into -- that is still tainted when the SEEDED function returns, and that another function can read, is a blocking `coarse_memory_store` leaf at the write: the walk never ascends past the seeded function, so those readers are not followed. A constant fill that covers every tainted byte on every path to the return -- `memset(g, 0, sizeof g)`, `bzero`, constant stores, or a callee that does so on entry -- clears it, and no leaf is raised. It carries `global` (`address`, `label`, `written_offsets`), `references[]` (one reader: the first that provably reads the bytes, else the first use that may, same row shape as below), `reads_proven`, and `unexamined_reference_sites[]` / `unexamined_references_total` (the other functions BN records a reference to the object itself from, at that reference, unclassified; a function that names only a preceding object is cited when its read provably reaches the tainted bytes and is otherwise never listed). No leaf when no other function references the object, or when a `global_memory_continuation` leaf already names it. A callee that fills a buffer through its pointer parameter (`copy_name(g, s)` -> `strncpy(to, ...)`) taints whatever the CALLER passed -- the global `g` here; when the caller's argument cannot be keyed either, the call itself is the `coarse_memory_store`. A heap block whose pointer is stored into a global and loaded back in the same function is the same block (`g = malloc(n); memcpy(g, s, n); strlen(g)`); when different paths store different blocks into the global, a reload may read any of them. A store into one field of a struct taints that field only: a load of another field is clean (a global struct, by the bytes each direct store recorded; a local struct, by `SET_VAR_FIELD`, also through a pointer passed to a callee), and a load at an offset the walk cannot establish is `field_load_unresolved`. In a `global_memory_continuation` leaf (and that store leaf), each `references[]` row is a use at the instruction that performs it -- a `cmp [g], 0; jne` read is cited at the `cmp`, where `bn xrefs` lists it; a `call_arg` row is cited at the call. A neighbour whose size is DECLARED is separate storage: only a use of it whose stated interval runs past its end into the tainted bytes is cited (as the read it is). An undeclared neighbour's use this walk could not bound is `access: "overlap_unverified"` (never a read; `reads_proven` stays false unless another row is `load`/`call_arg`), counted in `unverified_overlaps`; a pointer scan that ran out of a bound in a body with no reference to the object is listed in `unfinished_scans[]` (`name`, `address`, `at` where it stopped, `cause`), not as a reference. An object ends where it is DECLARED to: a type a user applied, the image's ELF `st_size`, or its debug-info type; BN's inferred types (including full-confidence initialiser-sized `char[N]`) are lower bounds only. An ELF `st_size` declares the object at its view address (`st_value` moved by the load bias: a PIE, or any rebased image). A rebased fixed-address executable (`ET_EXEC`) keeps naming the object at `st_value` in its unrelocated absolute references (immediates, initialised pointers); unless the view maps that address, it is a second spelling of the SAME object: a write or a use through either spelling keys the object at its view address (the `global.address` reported), and its declared width holds at both. BN records no reference to the unmapped link address (`bn xrefs` lists none there), so the functions naming that spelling are found by searching the executable segments' bytes for it (little-endian, as an absolute immediate or literal carries it); a search past its byte budget is disclosed as a truncated reference sweep. An object with no symbol ends at the next data variable BN recorded, not at the end of its section. With `reachability.cause: "object_extent_unproven"`, the prose names which of three reasons applies: a write past the layout bound, a write of unstated length into an undeclared object, or a neighbour's unbounded use (whose remedy retypes that neighbour, not this object).

**Writes at a runtime index (V5-01, D1-01).** A tainted write through `g + i` with an index nothing makes constant -- `strcpy(g + strlen(g), s)`, `g[i] = c`, or a callee writing through `g + i` it was passed -- taints the whole object `g`, recorded as reaching every byte of it from the base; no offset is added to `written_offsets` for it. A helper that fills a static buffer this way and returns its address therefore returns taint when the walk descends it, as it is assumed to when `--max-depth` stops at it. Unless BN's value set bounds the address and the write's length so that every byte it writes stays inside `g`'s DECLARED extent (a type a human applied, the symbol-table size or debug info), the write may also land in a neighbouring object, before or after `g`, which `g`'s taint does not cover: it adds a blocking `coarse_memory_store` leaf at the write with `global` (`address`, `label`) naming `g` and `index_bounded: false`. A write proven inside `g` adds no such leaf.

**The seeded function's own earlier read (V3-01).** The exit leaf also fires when the only reader is the seeded function itself, provided the read is a load that control reaches from the function entry without passing the tainting store. Function statics are the typical case (`c = table[cursor]; ...; cursor = n;`): the next activation, or a loop's next iteration, reads the stored bytes, and the walk never followed that. The leaf then carries `self_reread: true` (otherwise `false`), and its one `references[]` row is that load: `name` is the seeded function, `access` is `load`, `at` is the load. A load that every tainting store precedes reads this activation's value, which the walk followed, so it raises nothing. So does a load whose known offset and width touch none of the tainted bytes (`s.name` read before `s.port = n`).

**References the lifted body never names (V3-02).** A function counts as a reader only if some MLIL instruction in it names the object. If Binary Ninja records a code reference to the object but the function's MLIL never mentions any of its bytes, that function is not a reader. An example is an ARM PC-relative base (`add r3, pc`) that happens to land inside one object, while the load it feeds (`ldr r3, [r3, #off]`) reads a different object and the MLIL folds the intermediate away. A reference the scan meets but cannot classify is still cited as `unclassified`, with `offset_known: false`: where it lands in the object was not established.

**Stack probes.** A store that writes back the bytes it loads from the same address (`[a].q = [a].q`, how BN lifts the stack-clash probe `or qword [rsp+rax-8], 0` an `alloca` emits) changes nothing: it is neither a writer of loaded bytes nor a may-writer of a buffer or a pointer's object, so it adds no slice row, leaf or origin.

**Lifted-model scope (#954).** Every taint claim -- an all-clear, a complete slice, an origin -- is relative to Binary Ninja's lifted MLIL; where the lift erases machine semantics, the claim inherits the loss. Example: on x86-64, `mov byte [edi], 0` (an address-size-override `0x67` store through the low 32 bits of the stack pointer) is lifted as `buf[0] = 0`, a write of the full-address stack local (BN 6.1.10638-dev, build 256112377). Before relying on a complete slice or an all-clear for a specific access, compare its width and address calculation in `bn disasm <function>` or `bn il <function> --view llil` with the MLIL. Report a mismatch upstream to Vector 35 with the instruction bytes and the BN build `bn doctor` prints; bn does not repair the lift.

A forward flow whose `sink.via` is `abi_register` reached a modeled sink argument BN's recovered prototype dropped: the tainted value is in the argument's ABI register. Any flow whose model declares an argument BN dropped carries `sink.arity_mismatch`, **with or without `via`** -- a consumer keying only on `via == "abi_register"` misses the rows whose tainted argument was recovered while another declared argument was dropped. Its fields: `recovered` (the param count BN recovered), `dropped` (every dropped argument the model declares, e.g. the buffer of a bounded write), `register` (the ABI register the tainted arg was read from, null when it was recovered), `callee_ref` (the call target's address; null when it did not resolve), `callee_variadic` (true, false, or null when undetermined), `recovery_advice` (prototype-aware guidance shared by compact text and full detail), and `class_from`, which says what the class rests on. `model`: the tainted argument itself was dropped, so no bound is proven from the register read and the class is the model's own and **unproven** until argument recovery is complete (a bounded copy shows `overflow_len`). `recovered_args`: the class was decided from the recovered arguments only, without using the dropped ones; it need not match the class obtained with a complete prototype (a disclosure that needs a dropped argument, such as `length_shape: residual_chunk` without the buffer, is absent). No class is ever lowered from a register read, so the result can overstate but never hides a flow. The verdict marks such classes (`path_injection[1 via ABI register]`, `bounded_len[1 arity mismatch]`), the flow row says `(arg 1 via x1, arity mismatch)` or `(arg 1, arity mismatch)`, and a following line names the basis and the dropped args; inspect the prototype (`bn proto get <callee_ref>`) and repair only a demonstrated discrepancy with `bn proto set`, then re-run. Repeating a correct variadic declaration does not restore missing arguments. The one exception is a call to an import's PLT stub that BN typed with its IFUNC **resolver's** prototype (armv7 glibc: `memcpy` becomes `void* (*memcpy(int32_t hwcap))(...)`): that prototype is not the import's at all, so the call is routed through the import's model by name -- each argument up to the model's arity is read from the definition(s) reaching its convention register (a register a Thumb `ite` block fills on two paths is one argument carrying either value; an argument nothing proves leaves the call BN's arguments), the sink is classified like any other (no `via`, no `arity_mismatch`), and a caveat names the arguments and registers read that way. A backward `arg:` sink on such a call is seeded from the same definitions. A PLT entry is never reported as a split body. An unmodeled in-binary callee Binary Ninja did not analyse (too large, failed lift) is a caveat `in-binary X was not analysed (...)`, not `external X`, and is listed under `stats.analysis_incomplete_functions`; `bn decompile <addr> --force-analysis` analyses it. **Thunks.** BN's `is_thunk` flag only says a body ends in a tail call, so it only nominates a veneer and the MLIL decides: a flagged callee is resolved to its target only when its whole body is one tail call handing every one of its recovered parameters on unchanged, in order, at every hop (`j_memcpy`, a PLT-style stub); any other flagged body that ends in a tail call -- an -O2 wrapper that copies, allocates, swaps its arguments, drops one of them or calls helpers before its `jmp` -- is walked like any other body, tail call included. A body Binary Ninja skipped (`analysis_skipped`) is an `unread_callee_body` leaf with that `skip_reason` even when stale MLIL or the thunk flag remains, and a flagged body with no MLIL is one with `skip_reason: no_mlil`; neither is ever a prose-only caveat.

A reached `alloc_size` or `overflow_len` flow carries `sink.width_narrowing` (`{computed_width, parameter_width, at}`, widths in **bytes**, `at` the hex address of the arithmetic) when the length's LAST arithmetic (add, sub, mul, shift-left, negate) before the call ran in a narrower integer than the sink's length parameter -- `calloc(1, zx.q(n32 + 1))` wraps at `n32 = 0xffffffff` before the widening. Copies, zero/sign extensions and truncations are walked through; any other operation ends the check, so absent means no such narrowing was found, not that the length cannot wrap. Text shows it as a `width narrowing:` line under the flow. A memcpy-family copy whose destination is sized by the length is re-headlined `overread_len` only when the source may be shorter than the length; when the length IS the return value of a modeled fill (a model with `return_bound`, e.g. `recv`/`read`) of that same source pointer **and** BN's value set for the length at the copy is non-negative in the return's own width (a dominating `if (n <= 0) return;` gives `1..0x7fffffff`), the copy reads back only bytes the fill wrote, so it stays `bounded_len` with `sink.src_fill` (`{callee, at}`: the fill call). Without that proof the failure return (-1, `SIZE_MAX` once widened) is a possible length, so there is no `src_fill` and the source is sized like any other copy's -- usually `overread_len`. A check BN does not turn into a range (`if (n == -1)`, or a sign-bit test it does not narrow) proves nothing.

A backward `--sink arg:<callee>:N` or `trace --arg N` on a call whose recovered arguments stop before N is seeded from argument N's convention register when N is a position the callee's model declares a role for -- any copy, propagation or source operand, `len_arg`, `buf_arg`, `format_arg`, `first_dest`, the fortified guard `dest_size_arg`, a fill's `return_bound.max_from_arg`, and the other indexed fields -- so `arg:__strcpy_chk:2` reaches the guard however many arguments BN recovered. A position no role names is refused as out of range: nothing proves it is passed.

Forward taint reads native `MLIL_RET.src` return expressions even when the instruction's `vars_read` is empty. It treats BN's tail-call IL as a return: a modeled, descended, or conservatively tainted callee return reaches the caller's return even though the tail call writes no SSA result. Tainted arguments alone do not taint a callee whose return is clean. This also applies when forcing analysis splits an oversized body into tail-called pieces.

When BN's IL loses a return value, a `return_value_unrecovered` frontier (`unmodeled_callee`, never an all-clear) names the call. This happens in two ways. First, a callee whose recovered returns carry no value (an AArch64 identity function is a bare `ret`) while the call's result is used. Second, any call into an internal function the walk descends into with tainted arguments, to which BN's MLIL gives no result. bn does not check whether the caller uses the return register afterwards; read the disassembly after the call (`bn disasm <call> --linear 8`). The precision cost: a void function that receives tainted arguments also withholds the all-clear.

A scanf-family `call:` source seeds the model's whole destination range (`*arg:1..4` for `scanf`), whatever the format says. BN recovers a variadic call's arity from register writes, so a stale extra argument (on AArch64, often the stack-guard address) can get a conservative `source_seed_misanchored` leaf. That withholds the all-clear; it never drops a destination. When the format is a constant read up to its terminating NUL, each destination it writes that no seed covers is a blocking leaf, one cause per leaf. A destination BN did not recover an argument for (forwarded incoming pointers that stay in their argument registers, a tail call) is `format_destination_unrecovered` with `missing`: read the call (`bn disasm <call> --linear 8`) and seed those pointers by hand. A destination BN did recover that lies past the model's `*arg` run is `scanf_arity_residual` with `residual` and `residual_args`: extend the model with a `--models` overlay or seed those arguments. A `call:`/`ret:` preset whose call has no recovered destination at all is not refused: the run returns zero sinks with the blocking leaf. Only the format's start address is checked for read-only storage, so a format whose suffix lies in writable storage can be under-counted, and then gets no such leaf.

The ISO C spellings `__isoc99_*` and `__isoc23_*` of `scanf`, `fscanf`, `sscanf` and `vsscanf` resolve to the plain model: `call:scanf` finds a call to either, and the catalog lists them under the plain name with `accepted_aliases`; a presence row names the spelling `xrefs`/`callsites` should use, `resolved_symbol` (the exact model name when the image has it), as `[present as __isoc99_scanf]`, or plain `[present]` when that is the model name itself; JSON `accepted_aliases` lists every spelling present. Results name such a call by the callee rule above (`callee` `__isoc99_fscanf`, `model` `fscanf`), and text rows print the called name.

Prototype diagnostics distinguish determined variadic, determined nonvariadic, and unknown types. A correctly variadic callee's `...` arguments may exceed its named formals: an untracked handoff is a modeling frontier (`cause: varargs_not_followed`), not evidence that `...` is missing -- including a tainted argument register past its named formals that the call's MLIL does not carry (`registers`, `evidence`). Unknown types (`prototype_status_unknown`) require inspection before diagnosis; confirmed extra arguments disagreeing with a nonvariadic declaration (`signature_under_recovered`) support repair. Which argument registers a call's recovered arguments occupy comes from where the callee's prototype binds each formal, not from counting the convention's registers: a formal BN bound to the stack occupies none. An argument register written before an intervening call is that earlier call's (argument registers are caller-saved), and a callee "reads" a register only when its MLIL uses the entry value -- a prologue save (callee-saved `push`, Thumb `push {r3, lr}` alignment padding) or a loop phi nothing reads is not an input. Trace/defuse's nearby stack stores are candidates, not proven call arguments: format literals and contiguous offsets do not establish provenance. Incomplete recovery and tracking still withhold completeness/all-clear claims.

`param:N` selects recovered named formals, not a correctly declared variadic tail. An unavailable formal is not itself evidence that the signature needs repair. Backward aggregate advice for an opaque buffer writer recommends inspecting/modeling its writes and input propagation; a correct prototype alone does not provide a taint model.

Target-requiring commands in taint/trace/defuse hints, `callsites` notes, the `dataflow values` refusal and `decompile` warnings (text summary, `--explain` detail, JSON `warnings`/`warning_rows`) receive the run's missing target and instance selectors, on both success and refusal paths, including JSON. Existing explicit routing is retained. Lifecycle and other non-target recovery commands keep their own spelling and arguments: in particular, `bn session start` must not acquire an existing-instance `-i`. Concrete function, callee, and variable locators in commands are shell-quoted. Taint and trace caveat prose uses display names by default and raw symbols under `--mangled`; structural symbol keys and runnable command locators remain raw.

Use `--models FILE` for a known wrapper; keys are current symbol names (including `sub_*` on stripped targets) or a function's entry address (`"0x401000"`), which a command run against a target applies under that function's current name and discloses as the user overlay row's `resolved` map (`{"0x401000": "sub_401000"}`); an address that is no function start, an address and a name key naming the same function, and any address key with no target are refused (exit 2). Entries nest `sink` or `sources`. The file must be a JSON object (`[]` is refused like any list), every key at every level must be one the loader knows (or a `_comment*` note) -- an unknown key is refused naming its path (`sink.clas`) -- and `sink.class` must be a builtin class (`bn taint models --class` refuses an unknown one the same way, listing the valid set). For `app_recv(fd, len, buf)`, `{"app_recv":{"sink":{"class":"overflow_len","len_arg":1,"buf_arg":2}}}` models a bounded-write sink; `{"app_recv":{"sources":[{"to":"*arg:2"},{"to":"ret"}]}}` seeds its output buffer and return. A sink whose tainted args mix a buffer and a length names the buffer in `pointer_args` (`{"app_send":{"sink":{"class":"net_write","tainted_args":[1,2],"pointer_args":[1]}}}`); backward slicing reads that argument as a pointer the sink reads through and the other tainted args as values. `sources` is a list of `to` rules: `*arg:N` means the pointed-to buffer, `arg:N` its value, and `ret` the return. An entry that puts the sink-arming fields (`class`, `tainted_args`, `len_arg`, `buf_arg`) beside the symbol with no `sink` under it, declares no recognized role at all, or declares a role with nothing in it (`"sources": []`, `"propagates": []`, a `varargs` without `to`) is refused with the expected shape named; annotation keys beside a real role are left alone.

Overlay rules are the same for `taint models --models` and `taint forward/backward --models`:

- An **annotation-only** entry (`return_bound`, `arity_capped`, `destinations_unmodeled`, with no flow role) merges only into an existing **flow-bearing** model of the same name, preserving its flow roles. For example, `{"read":{"return_bound":{"max_from_arg":2}}}` keeps the builtin `read` buffer-source, return-source, and sink roles.
- An entry with **any flow role** — `sources`, `sink`, `propagates`, `writes`, `varargs`, or `continuation` — **replaces the entire model entry**, even when it also supplies annotations. Omitted roles are not inherited.
- A benign `{}` builtin such as `puts` is **not annotatable**: an annotation-only entry for it is refused, just as for a name with no existing model. To model flow, supply the flow role explicitly. Supplying `{}` instead replaces the entry with a benign marker.

For example, this mixed flow/annotation overlay replaces `read`; it keeps only the declared return source and return bound, dropping the builtin buffer source (`*arg:1`) and sink:

```json
{"read": {"return_bound": {"max_from_arg": 2}, "sources": [{"to": "ret"}]}}
```

The `models:` header counts only entries that carry a role; an empty `{}` or a `_comment`-only entry (a benign function that neither sources, propagates nor sinks taint) is reported separately as `benign`. `bn taint models` lists a `writes` role (`bzero`) under propagators as `literal->*arg:N`.

Every sink in a run carries `sink.detail`: a `--models`/`$BN_TAINT_MODELS` sink written without one gets a generated sentence naming its class, arming arguments and the file that declared it, and a sentence the author wrote is kept. The regex match APIs `regexec`, `re_search`, `re_match`, `pcre_exec` and `pcre2_match_8` are builtin propagators from the subject string to the match-offset array, so a copy sized by a match offset reaches its sink without an overlay. A fortified `__*_chk` sink names its compiler-supplied destination size as `sink.dest_size_arg`, a value: `taint backward --sink arg:__strcpy_chk:2` reports a constant guard as a `constant` sink-site row with its scalar, not as a pointer read. An overlay may set `dest_size_arg` too; it must be an argument index.

`bn taint models` with no target and no `-i` is served by the CLI without a bridge (same JSON shape): `presence_catalog: false` and a `catalog_note` saying the entries are modeled names, not symbols found in a binary. With a target, `presence_catalog: true` and `present_model_count` (distinct modeled names matching a symbol, within the role/class filter); at 0 the text prints `no modeled name matched a symbol in this binary: its sinks may be unnamed (stripped) internal helpers, so this is not an all-clear -- review internal copy/format/exec helpers by hand`. A BN `.synthetic_builtins` placeholder (`__builtin_memcpy`, ...) marks its model present only when code references it. Overlays are labelled by the knob that supplied them (`via`: `--models` or `$BN_TAINT_MODELS`); a `--models` flag that overrides a set `$BN_TAINT_MODELS` discloses the env file as `env_not_loaded`, and a missing or unreadable `$BN_TAINT_MODELS` file is refused (exit 2), exactly like a missing `--models` file.

Each `model_sources` row (a taint run) and `overlays` row (`bn taint models`) is one model layer, most specific last:

| overlay row `kind` | meaning | fields |
|---|---|---|
| `builtin` | the shipped model DB, always first | `path` |
| `env_override` | the bridge's own `$BN_TAINT_MODELS` file | `env`, `path`; `count`, `benign`, `resolved` when it is also the forwarded file |
| `override_default` | the default override file (`~/.cache/bn/taint_models.json`) with `$BN_TAINT_MODELS` unset | `path`; `count`, `benign`, `resolved` when it is also the forwarded file |
| `user` | the file the client forwarded | `via` (`--models` or `$BN_TAINT_MODELS`), `count` (entries that arm a role), `benign` (no-op markers, when any), `path`, `resolved` (address keys rewritten to function names, when any) |
| `env_not_loaded` | a set `$BN_TAINT_MODELS` file that `--models` overrode, so not loaded | `env`, `path`, `overridden_by` |

## Caller-static mapping

`bn callsites` returns native `call_addr` and post-call `caller_static` (the return address). Prefer it over hand-written `py exec` for exact caller mapping:

```bash
bn callsites parse_record --within process_message --caller-static
bn callsites parse_record --within-file /tmp/callers.txt --format json
```

`--within-file` accepts one function identifier per non-empty line, with `#` comments. Each text label (`call_addr`, `caller_static`, `containing_function:`, `callee:`, `hlil_statement:`, `pre_branch_condition:`, `arity:`, `call_index:`, the `context:` block's `call_instruction`) is the JSON key that carries the value. A tail call (`b callee`) has the HLIL statement BN renders for it (`return callee(a, b) __tailcall`) and the condition it sits under. `arity` is the finding `decompile` marks on that call: the argument registers the statement does not render with each value when known (`+1 arg not rendered: x1 = 0x4008e0 (on_packet)`), or that a no-parameter prototype's rendered arguments are BN's guess; a row without it had no such finding, which does not prove every argument is shown. A variadic callee's `callee_variadic` note prints `bn evidence function <caller address>` and `bn disasm <caller address>` for that row's caller, with this invocation's `-i`/`-t`. A null `hlil_statement` means BN could not localize a safe statement; JSON may include a bounded `decompile_excerpt` for context. The excerpt is built for the requested page, so use `--limit` to bound its cost. Caller enumeration can stop at its budget; a short list with `caller_scan_truncated: true` is not proof that other callers do not exist.
